# Design: changes/impeccable-design

## 1. Shape

```text
command (constitution/specify/test/validate/audit)
   └─ loads impeccable-bridge (packaged, MIT)
        ├─ Step 0 detection → installed | skill only | absent
        ├─ installed/skill only → route to the environment's /impeccable
        └─ absent → fallback chain (ui-ux-pro-max catalog + frontend-design craft + stitch-design mockups)
```

The bridge is the only place that names Impeccable commands, paths and flags. Commands say "load `impeccable-bridge`" and name the step; they never restate its rules.

## 2. Source of truth (D-3)

| Artifact | Role | Who writes it |
|---|---|---|
| `docs/ux-ui/design.md` | **Authority**: tokens, type, page modes per screen, design waivers | `/akili-constitution`, approved spec changes |
| `PRODUCT.md`, `DESIGN.md` (project root, Impeccable context) | Derived views; first line `<!-- Derived from docs/prd.md and docs/ux-ui/design.md — edit there -->` | Regenerated by the bridge from the authority |
| `.stitch/DESIGN.md`, `docs/specs/<spec>/mockup/` | Mockup input for one spec | `stitch-design` / Impeccable direction picker |

Why not root `DESIGN.md` as authority: every AKILI command, the Reviewer, and `/akili-audit` already read `docs/ux-ui/design.md`; moving the authority would touch every command and break legacy-path handling.

## 3. Existing-product evaluation (D-4)

`/akili-audit design [<target>]`: target defaults to the dev server URL from the TRD/package scripts, else the repo's UI directories. Steps: E0 bridge detection; E1 context (baseline if present, else infer and mark assumptions); E2 detector run (URL and source); E3 `critique` + `audit` per key screen, by page mode; E4 score and prioritize; E5 write report; E6 offer routes. Report template lives in `impeccable-bridge/references/design-evaluation.md`. Fallback without Impeccable: same template, heuristics from `ui-ux-pro-max` + `frontend-design`, detector rows `Unevaluated`.

## 4. Test plan

New `test/impeccable-bridge.test.js` pins: frontmatter, detection paths, fallback, source-of-truth rule, gate exit codes, privacy, no vendored upstream files (no `skills/impeccable` dir in the package, no `.impeccable` files), command wiring in six commands, audit report path, docs rows. `install-cursor.test.js` count 245 → 247.
