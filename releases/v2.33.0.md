# v2.33.0 - AKILI-SPECS methodology update

Release date: 2026-10-18

### Added

- **`/akili-security` audits a repository for security vulnerabilities with a vendored, pinned skill (release classified minor: new command, `changes/akili-security`).** The command runs the packaged `security-audit` skill in full audit mode and owns the gates around it: a preflight (skill copy checked against `adapted-for: "AKILI-SPECS"` and the pinned commit, `node --version`, sub-agent capability), a **plan gate** that stops on every run and a **routing gate** that stops whenever it is reached — only a run that writes an index reaches it (the command runs outside any spec, so it has no Approval Mode and no pre-approved mode), an **execution gate**, and a **validator gate** after Phase 4 and every Phase 5 replacement. Every run is **static-only**; sandboxed execution applies to that run only, when the user selects it at the plan gate and confirms a sandbox enforcing all four upstream controls (no external network, allowlisted empty environment, read-only target, resource limits), and on every run nothing installs dependencies, fetches from the network, or probes deployed endpoints. Full findings live in a run directory outside the target (or an ignored directory the user picked, never under `docs/specs/`); the only tracked file the command writes is one redacted index, `docs/specs/audits/security-<YYYY-MM-DD>[-<safe-branch>][-N].md` — verdict, execution policy, validator results, counts, and one row per `confirmed` / `needs_validation` record by opaque id `S-n`; finding titles and fingerprints appear only in a detailed index the user opts into at the routing gate for a private repository. The run path is written as `~/…`, repo-relative, or `<external>/run-<N>`. The routing gate prints `/akili-propose bugfix/security-<YYYY-MM-DD>-s<n> <pointer>` for each `confirmed` record the user selects and creates no spec, proposal, task or code change. With no sub-agent capability, **Guidance review** replaces **Run** (findings in conversation, no artifacts, no index). `README.md`, `docs/commands/` and `docs/flow.md` name the command, `AGENTS.md` (*Skill Usage*) names the skill and the command, and `docs/cli.md` carries the new counts; installs now carry 12 commands and 25 skills (`npm run verify:cli`).
- **The `security-audit` skill is vendored from Cloudflare (`binding: core`).** Author Cloudflare, Inc.; licence MIT (upstream `LICENSE` copied into `.claude/skills/security-audit/`); pinned at `cloudflare/security-audit-skill` commit `c1c8a8c1471069fb0e188eeaff69b8e8db6564a8`; adapted for AKILI-SPECS by Juan Carlos Cadavid (only `SKILL.md` is edited — frontmatter plus an `## AKILI-SPECS Integration` section). The 19 files are the method, ten domain guides, `report-schema.json`, the two `.cjs` validators and `LICENSE`. The two upstream `validate-*.test.cjs` files are **not** packaged: on Node 18, `node --test` runs any `*.test.cjs` under `.claude/` (measured: Node 18.20.8 → `# tests 2`; Node 22.12.0 and 22.23.3 → `# tests 1`), which would execute them in this repo's CI and in any user project with a `--local` install whose `npm test` is `node --test`. `test/security-audit-skill.test.js` replaces them with AKILI-owned smoke cases (file set, attribution, licence, the validators' exit codes on a valid and an invalid input, and an `--tool claude` install). `docs/skills/security-audit.md` carries the attribution, the re-sync procedure and the governance checklist. Package growth: `npm run pack:dry-run` unpacked size 4,494,174 B → 4,802,046 B (+307,872 B, within the 320 KB bound).

### Changed

- **Drift-report readers are scoped to `drift-*.md`, so a `security-*.md` index in `docs/specs/audits/` is never read as a drift report.** `/akili-audit` (*Reading reports back*), `/akili-archive` (the drift source), and the `kaizen` skill (the drift-attributable row) each take the most recent report from the `drift-*.md` files only, and say a `security-*.md` index is not one; the legacy `docs/specs/drift-report.md` fallback applies only when the directory holds no `drift-*.md` file. `/akili-constitution` scaffolds `docs/specs/audits/` with a `README.md` that names both prefixes (`drift-*` per `/akili-audit` run, `security-*` per `/akili-security` run).

### Notes

- **`/akili-security` is not supported on native Windows (fails closed).** The vendored validators open their input with `O_NOFOLLOW | O_NONBLOCK` and refuse to run when `fs.constants` lacks either (`OS no-follow and nonblocking input protection is unavailable`, exit 1); Windows has neither, so on Windows no finding can be validated. The first CI run on both Windows legs (Node 18 and 22) failed exactly `validate-findings.cjs exits 0 on [] and 1 on an incomplete finding`. The command's Step 0.2 preflight now stops before the plan gate — on every path, including Guidance review — when `process.platform` is `win32` or either constant is `undefined`, names the reason, and points to WSL, Linux or macOS; `docs/commands/akili-security.md`, `docs/skills/security-audit.md`, `docs/flow.md` and `README.md` say so. The validators stay byte-for-byte at the pinned commit (no patch). `test/security-audit-skill.test.js` now expects exit 1 plus that message on a host without those constants, and `test/akili-security-command.test.js` pins the preflight wording.
- **No model-routing row for `/akili-security` yet (deferred, with a follow-up bug).** `docs/model-routing.md` and `.claude/templates/model-routing.section.md` are unchanged: a template edit makes `akili routing` refuse every existing project's fence as hand-edited (`bin/routing.js:431-436`), and a row added only to the doc makes `/akili-audit` report a packaged-only phase as Phase→Tier Drift. The command's own model checkpoint states the tiers (T1 Leader, T3 Auditor). The follow-up Bug is that template evolution is misread as a hand edit.
- `bin/`, `.claude/templates/`, `docs/model-routing.md` and `package.json` are unchanged against the base commit `6d1e152` (`git diff 6d1e152 -- bin/ .claude/templates/ docs/model-routing.md package.json` → empty).
- Verified locally on Node 18.20.8 and 22.12.0 (`npm test` → 326 pass, 0 fail on each, including the 61-test `/akili-security` text-contract suite). **Windows is unsupported** (P-13, measured by the first CI run, 39160826587): see the first note. Linux Docker images (`node:18`, `node:22`, bare) fail one case, `tasks-gate`, because `jq` is absent; it reproduces at the base commit, so it is an image gap, not a regression of this change.
