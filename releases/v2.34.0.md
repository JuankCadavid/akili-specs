# v2.34.0 - AKILI-SPECS methodology update

Release date: 2026-10-19

> This release (classified **minor**: two new conditional skills, `diagram-design` and `video-production`) integrates three archived specs: `changes/antigravity-argon-registry`, `changes/archify-diagrams` and `changes/video-deliverable-track`.

### Added

- **`diagram-design` skill (`conditional`, `changes/archify-diagrams`).** Every filled diagram slot in the baseline and spec documents is an inline Mermaid block with a legend; a slot catalog (`references/slot-catalog.md`) holds each slot's condition, Archify type, and Mermaid type, and a slot whose condition is false leaves nothing in the document. When the `archify` skill is available, the slot also gets an interactive HTML view linked directly under the Mermaid block; without it the document stays complete and no phase is blocked. `/akili-constitution` Steps 3, 4 and 5 and `/akili-specify` Step 2.1 (architecturally significant designs) each gain one conditional line loading it; `/akili-archive` Step 2 gains summary item 11 "Diagrams" (links to the spec's views, and baseline slots the design made stale as follow-ups). Archify (tt-a1i, MIT, https://github.com/tt-a1i/archify) is referenced and never vendored: the package ships no Archify file, and installing it (`npx skills add tt-a1i/archify`) is the user's choice, documented in `README.md`.
- `docs/skills/diagram-design.md` and a `docs/skills/README.md` inventory row; `docs/skills/governance.md` lists `diagram-design` under `conditional` and `archify` as an environment-provided example.
- **A video deliverable now has a track through the flow: `Deliverable: software | video` (`changes/video-deliverable-track`).** A new `conditional` skill, `video-production`, bridges the AKILI phases to the installed HyperFrames skills: an availability gate, a phase map, and privacy and render rules. Nothing from HyperFrames is vendored and AKILI does not install it; when the router skill is missing the gate stops and prints the install routes. Where each command reads or writes the selector:
  - `/akili-propose` records `Deliverable` beside `Type` (default `software`; an absent row reads as `software`); a `Trivial` video continues as a Lite proposal and is never routed to `/akili-quick`.
  - `/akili-specify` runs **Video Mode** when the proposal says `Deliverable: video`: it copies the row into `requirements.md` Document Control, loads `video-production`, writes measurable video acceptance criteria, and keeps the storyboard beat table in `design.md`. For a Bug, the regression test is a frame or metadata check at the failing timestamp.
  - `/akili-test` plans a render evidence suite in place of unit/E2E for the video tasks; a missing HyperFrames install is the same STOP as missing test infrastructure.
  - `/akili-validate` will not report PASS without a recorded, approved final look at the draft render, and runs the local delivery render only after that approval.
  - `/akili-quick` sends a video composition edit to `/akili-propose`, since it cannot produce render evidence.
  - `/akili-constitution` Step 8D names `video-production` as the AKILI route for the `hyperframes` Skill Map row; the Leader template lists it as a swap-in example.
- **Governance rule 4 and a narrowed rule 2 (`docs/skills/governance.md`).** Command text may direct the load of an environment-provided skill only behind a `Deliverable` selector and that skill's availability gate; illustrative and Skill Map-builder mentions are exempt. Rule 2 (availability is per-developer, not per-project) gains one narrowing: a spec whose `Deliverable` selects an environment-provided skill stops at that skill's availability gate. Docs updated: the `video-production` skill page, the skills index, `README.md`, `AGENTS.md`, `docs/flow.md`, the command pages, and the `docs/cli.md` skill count (25).
- **Live-smoke findings folded into `video-production` (A3).** Before the first render on a machine the skill has the user consent to HyperFrames' own runtime caches (a ~200 MB headless browser in `~/.cache/hyperframes`, run state in `~/.hyperframes`) and to network use (CDN scripts, web fonts); `npx hyperframes skills check` is documented as reading only the global skills directory, never a project install; the render-evidence duration tolerance defaults to ± 0.1 s when the requirement states none.

### Changed

- **Antigravity's packaged roster routes T1 and T3 to Gemini 4 Argon (`changes/antigravity-argon-registry`).** In `.claude/templates/model-registry.json` and the `docs/model-routing.md` table, Antigravity's T1 Architect and T3 Auditor are now `gemini-4-argon-high`, with `claude-sonnet-5-5-high` as the T3 fallback; the retired ids `gemini-3.1-pro-high` and `claude-sonnet-4-6` are removed from the Antigravity roster, and its `lastVerified` is `2026-10-18`. The `gemini-3.8-flash-{high,medium,low}` entries keep their `flash` wrapper model. **Argon roles get no wrapper:** an Antigravity wrapper's `model:` accepts only `inherit`, `flash` or `pro` — `agy plugin validate` (2026-10-18) rejected every Argon spelling tried with `Invalid model tier` — so the Argon entry carries no `wrapperModel` and the Leader and Reviewer are skipped with a `no wrapper` report instead of being written with an unconfirmed value; the Implementer and Tester keep their `flash` wrappers, and the Step 8E Antigravity example in `/akili-constitution` now shows the Implementer wrapper (`model: flash`), not a `pro` Reviewer. **Mitigation:** run the session on `gemini-4-argon-high` — an unwrapped Reviewer is a generic subagent that inherits the session model, so author ≠ auditor holds against the `flash` Implementer (the Reviewer is read-only by instruction, not by a `tools` restriction). **Expected on upgrade:** re-run `akili routing` with `--models antigravity=gemini-4-argon-high,gemini-3.8-flash-high,gemini-3.8-flash-medium,gemini-3.8-flash-low,claude-sonnet-5-5-high`; a plain re-run from the answers file drops the retired ids and degrades to author ≠ auditor NOT satisfied with all four wrappers skipped — the silent degrade is a known configurator defect, to be fixed separately. **Known debt:** `.claude/templates/model-routing.section.md` still names Gemini 3.1 Pro on its Antigravity line, pending the template-evolution bug (editing that template makes `akili routing` refuse existing fences). Step 8E's `/agents` check and wrapper list in `/akili-constitution` now match the skipped Leader and Reviewer.
- `software-architect`'s `views-documentation.md` now points to `diagram-design` for diagram slots, storage, and the optional interactive view (Mermaid stays the default renderer).
- **Packaged skill count 25 → 27 (`diagram-design`, `video-production`).** `docs/cli.md` says 27; `test/install-cursor.test.js` pins 223 skill files (was 218 in 2.33.1: 2 for `diagram-design`, 3 for `video-production`) and its count comments read 235 shared-root files, 27 skill directories and 39 operations (were 230, 25 and 37); `test/fixtures/doctor-codex-baseline.txt` lists both skills (`ok 47`, was 45).
- **`video-production` file inventory.** Four packaged files are new: `.claude/skills/video-production/` (`SKILL.md`, `references/acceptance-criteria.md`, `references/render-evidence.md`) and `docs/skills/video-production.md`; every other packaged change is an edit to an existing file.

### Fixed

- **`akili routing` no longer reports that `/agents` lists only `akili-leader` when no Leader wrapper is written.** `bin/routing.js` emits `Antigravity: in-session \`/agents\` lists only \`akili-leader\` — that is the success condition` only when the Leader wrapper is planned; on the packaged roster (Leader routed to Argon, no wrapper) the line is absent and the `Antigravity Leader: no wrapper` and `Antigravity Reviewer: no wrapper` lines stand alone.
