# v2.40.0 - AKILI-SPECS methodology update

Release date: 2026-10-30

### Added

- **Impeccable 4.8.0 is now vendored verbatim under `.claude/skills/impeccable/`, installed into all six targets (31 packaged skills, was 30).** It is Impeccable by Paul Bakaus (`pbakaus/impeccable`, Apache-2.0) at upstream commit `df3a4ab` (engine 0.1.18): 58 upstream files plus `LICENSE`, `NOTICE` and `UPSTREAM.md` (the pin and a sha256 per file), 61 files in all. The only change to upstream is an AKILI `metadata` block added to the `SKILL.md` frontmatter. AKILI-SPECS is not affiliated with the Impeccable project. The pin moves only through the maintainer script `scripts/sync-impeccable.js`, which is not shipped; `docs/release-checklist.md` has a step that compares the pin with upstream's latest release.
- **The installer protects a user's own `impeccable/` folder.** An existing `impeccable/` folder with no `UPSTREAM.md` is skipped and reported as `skip foreign`; on targets without an ownership record its version is shown when readable (Grok Bot reports `skip foreign` without it). `akili install --force` replaces it whole: the folder is moved aside first and put back if the install fails.
- **`impeccable-bridge` is now v2.0 and owns the engine gate.** A design step first records the skill source (`vendored`, `user-installed` or `missing`) and the engine state (`ready`, `consent needed`, `installed (consented)`, `declined` or `unavailable`), which replace the old `installed`/`skill only`/`absent` triple. The engine probe runs with no download, the found binary is pinned with `IMPECCABLE_BIN`, and the engine is downloaded only after an explicit yes in every approval mode. With no engine, detector rows read `Unevaluated (engine not installed)`.
- **The detector launcher form is `DO_NOT_TRACK=1 IMPECCABLE_NO_UPDATE_CHECK=1 <launcher> detect --json …`, and every AKILI launcher run carries `IMPECCABLE_NO_UPDATE_CHECK=1`.** `DO_NOT_TRACK` does not stop the engine's update check; the bridge cites upstream's CLI contract for this.
- **The bridge adds a first-visit pass, proposed waivers and viewports.** Persuade and Operate screens get a fold screenshot and a hit-test at the primary CTA with consent and overlay hiding off; without browser automation, `/akili-validate` asks for a manual fold check at the HITL pause; with none recorded the gate is `WARN (unverified first visit)`, never `PASS`. In `/akili-audit design` (report-only), a finding that matches an approved design pattern with no waiver row reads `Proposed waiver (<clause>)`, is counted in the header and not in P1–P3, and is never written to the authority. URL scans run at a desktop and a mobile viewport (`390x844` unless `docs/ux-ui/design.md` declares one).

### Changed

- **`references/design-evaluation.md` gains a performance step, E3b.** It runs at least 3 mobile Lighthouse runs per URL and reports the median and range of the score and of LCP; one run is never the score. The report header adds Mobile viewport, Baseline, Out of scope, Performance, Proposed waivers and Report location, and the template adds Scan matrix, Capture conditions and Performance tables.
- **`/akili-validate`, `/akili-test` and `/akili-audit` carry a per-value table of what each engine state means for that step.** `/akili-constitution`, `/akili-specify` and `/akili-propose` point at the bridge, as do `ui-ux-pro-max` and `frontend-design`.
- **`docs/skills/governance.md` adds the category *Vendored third-party (verbatim)*,** with the rules for an unmodified upstream build, a declared frontmatter-only change, the three attribution files, a hash-locked test and sync through the script.

### Notes

- **Release class: minor** (a new vendored skill, a new installer outcome and a re-scoped bridge; no new command or install target).
- **This supersedes `changes/impeccable-design` NFR-1 ("never vendored") from 2.39.0.** The 2.39.0 entry above still describes the earlier state.
- **Disclosure.** The engine gate governs AKILI steps only. Invoking `/impeccable` directly, outside an AKILI command, follows upstream behavior, including the launcher's first-run engine download.
- **Package size.** Measured with `npm pack --dry-run` against 2.39.0: about +834 KB packed (2.76 MB → 3.59 MB) and +2.28 MB unpacked (5.83 MB → 8.10 MB), 62 more files (345 → 407: the 61 vendored files and `docs/skills/impeccable.md`).
