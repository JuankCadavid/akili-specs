# v2.33.1 - AKILI-SPECS methodology update

Release date: 2026-10-19

### Fixed

- **Ctrl-C at either `akili init` question now writes one newline and exits with code `130`; nothing is installed (patch, `bugfix/init-ctrlc-abort`).** Before, the wizard's two questions used a bare `rl.question`: on Node ≥ 22.23 (observed on 22.23.3) Ctrl-C printed an unhandled `AbortError: Aborted with Ctrl+C` stack trace and exited `1`; on Node ≤ 22.12 (observed on 22.12.0) it exited `0` silently. Both questions now go through a shared helper in `bin/akili.js` holding the abort handling extracted verbatim from `akili routing`'s typed question, and `runInteractiveInit` turns its tagged abort into exit `130` before any install argument is built. Prompt text and the answer → install mapping are unchanged. `akili routing`'s Ctrl-C is unchanged: it still exits `130` through the same helper, and `test/routing-pty.test.js` passes as before. A new regression test, `test/init-pty.test.js`, drives `akili init` on a real pty through `expect` (`test/fixtures/init/pty-init.exp`) in three cases — Ctrl-C at the tool question, Ctrl-C at the scope question, and both questions answered — and asserts `RC=130` with no trace line, no `AbortError` and no install target for the two Ctrl-C cases, and `RC=0` with the option lines verbatim and `~/.claude/commands` created for the answered case. A fourth case, which needs no pty, runs `akili init` with stdin on the null device and asserts exit `130` with no trace line, no `AbortError` and no install target: end-of-input before an answer (`</dev/null` or a closed pipe) now also exits `130` with nothing installed, where it was a silent `0` on the baseline. It runs offline: the scratch `HOME` is seeded with a fresh update cache that must stay byte-identical, and a `--require` preload (`test/fixtures/init/no-network.js`) records any `https.get`/`https.request` call. The three pty cases skip on Windows, or when `expect` is not on `PATH`, with a printed reason, and copy their transcripts to `AKILI_PTY_LOG_DIR` when that is set; the end-of-input case runs on every OS. `docs/cli.md` → *Init* states the Ctrl-C contract. No new dependency; nothing under `test/` enters the package tarball. Verified locally with `npm test` → 331 pass, 0 fail on Node 18.20.8, 22.12.0 and 22.23.3 (rebased on v2.33.0); the Windows and Node 18 CI legs are the evidence for the pty skips and the `AbortError` fix on those hosts.
