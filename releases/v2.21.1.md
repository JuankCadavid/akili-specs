# v2.21.1 - AKILI-SPECS methodology update

Release date: 2026-08-02

### Added

- **The Tester side of the TDD no-duplication contract gets its missing carrier.** Auditing how 2.21.0's `tdd` adoption is actually wired surfaced a one-sided promise: the skill states that `/akili-test` Testers *"cite existing TDD coverage in their per-scenario matrix instead of rewriting it"* — but Testers never load `tdd` (they load suite skills), and neither `tester.md` nor `/akili-test` carried the instruction, while the tester rule "never mark a requirement covered just because related code exists" pushed in the opposite direction unopposed. Risk: duplicated suites — MUDA paid on every future test run. Two edits close it: `/akili-test`'s slice rules now have the Leader pull red→green test-file paths from `execution.md` task entries into the affected suite's slice with a **cite, not rewrite** instruction, and `tester.md` gains the counterpart — *author TDD coverage is evidence, not territory*: a named, passing author test is the documented exception to the covered-by-assertion rule (an author test that does not actually assert the scenario is still a gap), and the Tester's budget goes to what the author's loop does not prove (negative constraints, integration, E2E). Also fixed the inventory drift the governance doc itself forbids: `tdd` now appears in the *Current assignment* `conditional` row, with its assignment mechanism named explicitly (per-task Leader judgment via `leader.md`, not a conditional line in command text — the documented exception to the wiring norm).
- **Exemplar-file briefing — few-shot prompting enters the delegation loop as a pointer, not an anthology.** LLMs follow a worked example more reliably than any list of conventions (a principle underlined at AWS Summit LATAM 2026, and the reason the methodology's best-followed skill, `kaizen`, ships a fully worked log example while most command output formats ship schema only). The cheapest, highest-leverage application in AKILI is the Implementer brief: `/akili-execute` Step 2.2 now has the Leader name **the existing file most similar to what the task produces** as a pattern anchor (*"mimic `src/modules/orders/orders.service.ts` — structure, naming, error handling, test layout"*), chosen via CodeGraph or the module tree. One line of brief replaces paragraphs of style prose, and it respects the injection-scope economics — personas re-read on every spawn carry a *pointer rule*, never embedded examples. Guardrails built in: constitution and design spec win over the exemplar on conflict, and the Leader skips it when nothing comparable exists — a forced, dissimilar exemplar teaches the wrong pattern. Wired three places: the brief bullet in execute, **exemplar-file briefing** in the `leader.md` template spec, and **exemplar mimicry** in the `implementer.md` template spec (Step 8B). The companion Summit principle — small tasks with near-certain success — needed no change: it is already load-bearing doctrine (one-session task rule, 3-attempt rework ceiling, LOC budget with PR splitting, TDD tracer bullets, Maurer small steps in `kaizen`).
- **ADR supersession is now wired end-to-end — an architecture change on an in-flight application has a named path instead of an implied one.** The `software-architect` skill always had the pieces (8-field ADR profile, `superseded by ADR-MMM` status, ADR index in the TRD), but no command step connected them when the architecture actually turns: the Pivot Protocol modified the spec's own files without ever mentioning the TRD, and `/akili-archive` promised "keep the TRD current" in its description while its Constitution Sync step never named the ADR index. Three minimal edits close the loop, all enforcing the same invariant — **decisions are never edited in place; they are superseded, and the trail of why the architecture turned is the asset**: `/akili-specify` Step 2.1 records a design decision that overturns an existing TRD ADR as *superseding* (naming the old `ADR-NNN`); `/akili-execute`'s Pivot Protocol requires an architectural pivot to name the affected ADR in the `## Pivot Record`; and `/akili-archive` Step 3 gains an explicit **TRD & ADR sync** item that appends the superseding entry (Issue citing the pivot/design evidence) and flips the old one in the index. Prompted by the ADR practices presented at AWS Summit LATAM 2026.
- **Two field lessons upstreamed from a project's Kaizen retrospective into the packaged persona templates — the first real round-trip of the Product/Methodology loop.** A downstream session's `/akili-archive` produced two persona rules that name nothing project-specific, which makes them template gaps rather than local fixes: **`tester.md`** gains destructive-probe hygiene (a probe that mutates a contract, config, or tracked source reverts immediately after each run — never batch reverts to the end — and `git status` must be clean before the next probe, because a killed turn leaves a mutated gate that a later green run reads as health), and **`reviewer.md`** gains the inherited-claim re-check (an `UNVERIFIABLE` claim inherited from an earlier task is a claim to re-check, not to accept — verify the premise still holds before it becomes a permanently accepted gap). Both land in the Step 8B template spec of `/akili-constitution`, so brand-new projects get them at scaffold time and active projects receive them through Safe Update's existing gap-detection append. The exercise also exposed a gap in `kaizen` itself: its lesson targets were exclusive (Product = local edit; Methodology = upstream proposal, no local edit), which mis-serves exactly this case — a generalizable persona rule deserves both. The skill now defines a **dual `Product + Methodology` target**: when a lesson names no stack, domain, or local convention, apply the local edit now *and* record the upstream proposal.
