# v2.35.0 - AKILI-SPECS methodology update

Release date: 2026-10-22

### Added

- **`akili install --tool grokbot` installs AKILI into Grok Bot, run on the Grok Bot box.** It writes the 12 commands and 27 packaged skills as `<name>/SKILL.md` folders under the workflows root (default `/home/box/agent-data/workflows`) and the persona templates, `digests.json`, scripts and `.mcp.json.example` under a sibling `akili` resources root. Roots are set with `--grokbot-target`, `--grokbot-resources-target`, `AKILI_GROKBOT_TARGET`, `--local` (`./.grokbot/`) or `--target <p>` (`<p>/workflows` + `<p>/akili`); `--local` wins over the env var. Commands are installed verbatim and best-effort: Grok Bot has no slash commands, so `$ARGUMENTS` and subagent steps may not apply. Grok Bot is the sixth target and is never part of `--tool all` or `--tool both`; `install`, `update` and `doctor` are supported only on the box and print no copy, `rsync` or `ssh` step.
- **Folders AKILI did not write are protected.** AKILI records the names it writes in `<resources root>/grokbot-owned.json`; a same-name entry not in that record is foreign, so `install` and `update` skip it (`skip foreign`), `doctor --fix` leaves it untouched, and `doctor` reports it FOREIGN, with `INCOMPLETE` and a non-zero exit. Only `install --force` takes a foreign entry over, by moving it aside to `<resources root>/.takeover/`, recording the name, copying AKILI's folder in and then deleting the moved-aside copy. An invalid record is never overwritten and blocks every write into the workflows root (`install` and `update` exit 1, with the recovery steps printed). Accepted limits: ownership is by name, and `doctor --fix` restores a partial entry only when its `SKILL.md` is missing. See `docs/cli.md` > *Grok Bot*.
- **`/akili-seo` gains an optional analytics phase, Phase 2B: GA4 and Microsoft Clarity (`changes/seo-analytics`).** It is optional, asked once at Phase 0 and never repeated; declining records `Analytics: not run — declined at Phase 0`, skips Phase 2B and completes Phases 1–5 as before. The phase is read-only toward GA4, GTM and Clarity and has four steps: **2B.1** detects each tool with a rendering fetch and checks access (a static fetch alone never reports a tool absent; with no rendering tool an installation check is `not determined`), **2B.2** audits installation (tag and IDs, loading, consent, conversion events, GSC link, Clarity masking), **2B.3** reads aggregate GA4 and Clarity data, and **2B.4** joins Search Console clicks to GA4 sessions and key events per landing page. When neither tool is detected, 2B.2–2B.4 are skipped with `Analytics: skipped — no GA4 or Clarity detected` and exactly one Low finding, "conversions are not measured", is raised only when the sampled pages carry a form or a WhatsApp link.
- **Optional prerequisites 6–7 never stop the run.** GA4 needs the Data API and Admin API enabled with the service-account email as **Viewer** on the property, or the official Google Analytics MCP started without `--allow-write` (its write tool is never called); Clarity needs a Data Export API token supplied at run time and never stored. A missing item skips only its part of Phase 2B. The Clarity budget is 3 requests per run against a quota of 10 per project per day, and the report states the number used.
- **Consent findings are compliance signals, not legal advice.** Each carries a **Basis** with its tier and the sentence `Other jurisdictions: not audited`; a hit sent, or storage set, before the banner is answered is written "signal inconsistent with the consent requirement under <rule>", never a "compliant" verdict. Ley 1581 de 2012 is scoped to *datos personales* (Art. 3(c)) and is never cited as a cookie-banner mandate. The GSC link is settled in order: a Data API probe for a Search Console metric, then owner confirmation, then `not determined`.
- **The audit report gains sections 11–13 and a Measurement & Compliance group.** Section 11 is Analytics Installation Findings, 12 is Analytics Data Findings and 13 is Search → Conversion; each holds findings, a skip note, or `Analytics: not run — declined at Phase 0`. Remediation Plan and Re-audit Schedule move from 11–12 to 14–15, and analytics findings sit in a separate **Measurement & Compliance** group, so a High crawl finding and a High consent finding keep their own positions. The closing checklist gains items for the analytics state, consent Basis, the Search → Conversion caveats and a no-secrets-or-personal-data rule.
- `.claude/skills/seo-audit/references/analytics.md` (new): the method, checklists and sources by tier for Phase 2B; `npm run pack:dry-run` lists it. `evals.json` gains eval ids 10 (analytics run with rage clicks and a ranking question) and 11 (no analytics, contact form), 11 evals in all. `docs/commands/akili-seo.md`, `docs/skills/seo-audit.md`, `docs/skills/README.md` and `README.md` describe the phase.

### Changed

- **Docs and help name six install targets.** `README.md`, `docs/cli.md`, `AGENTS.md`, `CONTRIBUTING.md`, `.claude/README.md` and the `--tool` help now count Grok Bot, and the claims that hold only for `--tool all` say "the five desktop tools".
- **The behavior-metric rule now covers every behavior metric, in both directions.** Never claim that a behavior metric affects Google or Bing ranking, and use behavior metrics for conversion and UX findings only. The full list (bounce or engagement rate, session duration or engagement time, scroll depth, heatmaps, recordings, dead/rage/quickback/error clicks) appears in `references/analytics.md` §2, `seo-audit` *User Engagement Signals*, `/akili-seo` Step 2.8, Phase 2B and the Verification Checklist, and `docs/skills/seo-audit.md` Core Rules; `seo-audit` *Do not raise these* and *Analytics & Conversion Measurement* state the two halves without the list. Before, the command's checklist named only bounce rate and time on page.
- **The Google statement is tiered `[INDUSTRY]`.** `seo-audit` now reads "Google has said it does not use analytics engagement metrics as ranking factors (`[INDUSTRY]`, as reported); this skill extends the rule to all behavior data", replacing the untiered "Google does not use analytics engagement metrics as ranking factors." The `references/analytics.md` quotes (Cutts, Illyes, Mueller) are marked as reported by Search Engine Journal, and no Search Central text page was found.
