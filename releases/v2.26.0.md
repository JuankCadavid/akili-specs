# v2.26.0 - AKILI-SPECS methodology update

Release date: 2026-09-19

### Added

- **Premise Ledger — a `design.md` section auditing what a design takes as given (`changes/premise-ledger`).** `/akili-specify` Step 2.2's *Minimum content* gains an eleventh item, **Premise Ledger**, and its Guidelines gain the block that is the methodology's single definition of it: a **premise** is a statement the design makes about the *existing* system — code, data, environment, contract, or standing rule — that it takes as given rather than creates. A claim earns a row only when its falsity would change a design decision, a task, or the scope (the **dependence test**); trivia stays out, and the rows are written before the decisions that lean on them, because a decision already written reads as its own justification. Each row is a fixed seven-column shape with a stated absent-value per column, opened by a count line and a trigger line; the classes are a closed set of seven, four admitted by the dependence test (one of them the stated fall-through for anything the named classes do not fit) and three required only when their blast-radius trigger fires, with `Blast-radius triggers: none apply — <reason>` written in full when none do. The trigger for shared state fires on a condition or signal more than one block or component reads, not only on state, a service, a base class, or a lifecycle hook more than one component uses. A sibling is any reader of that state, condition, or signal, a conditional block in the same template included. Five citation rules each ship with the reading that falsifies a row claiming to meet them, and a fact stated by a person — the user included — is recorded `UNVERIFIED` until a primary source confirms it. `UNVERIFIED` is a visible state, never a blank or an omitted row: it carries the marker byte-identical to the one `/akili-execute` Step 2.2 clause (c) uses, so one grep finds every open fact in a spec folder, and names the settling check plus one owner. A design naming no existing code, data, contract, or rule writes `Premise Ledger: none — <reason>` instead — an absent section is never a valid empty state (KZ-004). Lite, Standard, and Full carry the same shape with no minimum row count. Three cases hand off through task fields that already exist — a consumer row into the owning task's `Consumers` beside what Step 3.2's Consumer Sweep finds, an `UNVERIFIED` row settled as that task's first step, a refuted premise to the Pivot Protocol — and every other class acts only through its *If false* cell. Around the block: Step 1.2 and `/akili-propose` Step 2 now require each current-behavior claim to carry a citation as run or the marker inline, never a bare fact; Step 2.1 verifies premises while the code is still open and has delegated scouts return citations as run; Step 2.5 prints the count line and every open row in full, recommending **Review Design** when one carries `High` Impact without gating **Continue**; the Verification Checklist gains four items; and `/akili-constitution` Step 7 item 2 names the section in the scaffolded `docs/specs/general-setup/design.md` template, inheriting the shape rather than redefining it. Mirrors (`docs/commands/akili-specify.md`, `akili-propose.md`, `akili-constitution.md`, `docs/skills/judgment-day.md`) and `docs/flow.md` brought to parity.
- **`judgment-day` attacks the Premise Ledger first, at the source (`changes/premise-ledger`).** A new Hard Rule puts the ledger before any other reading: judges re-run or re-read every citation, try to refute every `UNVERIFIED` row with their own search, and look for depended-on premises that carry no row — a premise is never accepted because the requirements and the design agree on it, only the source settles it. A row the citations cannot settle is attacked rather than merely scored: a citation cell holding neither a citation as run nor the `UNVERIFIED` marker, and a citation naming a secondary source rather than the primary one, are both attacked as though the row carried the marker — the judge searches for the primary source itself and reports what that search returns, including `not re-run` where its host cannot reach that source. Re-reading a document settles that document, never the system it describes, so a document that agrees with the design is not confirmation, and recording a severity without attempting that refutation does not discharge the rule. Which sources count as secondary is set by the block's citation rules, not restated in the skill. The rule restates none of the block and sets only what a bad row costs, in a severity table (the source contradicting a premise, and a design that names existing code with no ledger or a false stated-empty line, are **severe**; a confirmed premise is not a finding). It also states that **read-only is not no-search**: a read-only judge writes nothing but may read and search the repository, and read history where the host allows; one that cannot run a cited command re-derives from the cited files and reports that row `not re-run`, never as confirmed. Two-judge confirmation still gates auto-fix, and a contradiction reported by one judge is recorded as suspect with its command as run so the architect settles it in a single re-run. Skill version 1.7 → 1.9.
- **A four-check Blast Radius in the Bug Diagnosis (`changes/premise-ledger`).** `/akili-propose`'s Bug Track replaces the diagnosis's loose impact-and-scope line with a named **Blast Radius** section of four checks, each recorded with its result and either its citation as run or the `UNVERIFIED` marker naming an owner. **Already fixed?** is a history query over the target files *and* the ticket ID, across all branches: it runs **first**, before any root-cause work, is never `n/a` even for a cosmetic bug, and a hit that fixes the symptom ends the proposal — reported to the user, no spec. **Live path?** runs as part of confirming the root cause, so a cause sitting on code the reproduction never reaches is not confirmed and the diagnosis reopens. **Siblings on the same state** and **Downstream consumers** are enumerations that run after the diagnosis and feed scope. The Review Checklist gains a matching item and the report to the user names the result. In Bug Mode those results become the design's Premise Ledger rows; when a proposal carries no Blast Radius section, `/akili-specify` Step 2.1 runs the same four checks during exploration.

### Fixed

- **Two stale pointers into `/akili-specify`'s design-approval menu (`changes/premise-ledger`).** The `judgment-day` AKILI-SPECS Integration table sent readers to "Step 2.3" for the blind dual review of `design.md`, and Step 2.3 itself called the same panel "the opt-in Step 2.4 pass". The **Review Design** option lives in Step 2.5 — *Present & Approve*; both now name it, and the judgment-day row also states that judges attack the Premise Ledger first.

### Notes

- Released as **minor** (classification confirmed at release prep, 2026-09-19): `design.md` gains a new required section and the Bug Diagnosis a new required block, and `/akili-specify`, `/akili-propose`, `/akili-constitution`, and `judgment-day` all read them — new methodology behavior rather than guidance refinement. The change is text only: no tool, hook, persona, or `/akili-execute` change, and no new command or install target. Backward compatible — a design written without the section reads as "no ledger recorded", no command fails on it, and existing spec folders need no migration.
