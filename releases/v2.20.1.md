# v2.20.1 - AKILI-SPECS methodology update

Release date: 2026-07-29

### Added

- **Idle is not delivered — the return leg of a dispatch fails the same way the send leg does.** Field lesson, recurring in one session: two review judges dispatched, both went idle **without delivering their findings**, while the coordinator kept waiting for reports that were never coming. An idle worker's turn has *ended* — nothing further arrives without new input — so waiting on it is waiting on nobody. `leader.md`'s dispatch section gains the third link of the delivery chain (confirm the target is live → verify the send landed → **verify the return arrived**): on idle-without-report, **poke once immediately** (a direct message demanding the contracted report wakes the worker and usually recovers a result produced but never sent), check whether the output landed in a file with the final send skipped, and only then treat the dispatch as failed and re-dispatch or apply the role's runtime-failure fallback. Prevention lives in the brief: state the report as the **turn's terminating action** (*"your turn does not end until the report message is sent"*), not as one instruction among many — workers reliably do the work and unreliably remember to mail it.
- **Context checkpoints: the methodology now recommends `/compact`/`/clear` at the moments where they are safe, instead of leaving the user to guess mid-task.** The agent cannot run either — they are host commands — but it *can see its own budget*, and AKILI's file-based design makes conversation context **disposable at phase boundaries** by construction: everything durable lives in the repo and `/akili-resume` rebuilds from files alone. That inverts the economics (reset is nearly free at a boundary, destructive mid-loop), so the discipline is about *where*, not *whether* — the same recommend-at-the-right-moment pattern as model checkpoints. Three checkpoints added: **`/akili-archive` Step 6** (the cleanest boundary in the methodology — spec closed, fully externalized → recommend `/clear` before new work), **`/akili-specify` Review Handoff** (execution reloads everything from spec files → recommend fresh session for `/akili-execute`), and **`/akili-execute` Step 5** (between tasks, state fully in `execution.md`/`tasks.md` → `/compact` keeping the session, or park + `/clear` + `/akili-resume`; fires even under `pre-approved` mode since it costs one line, not a pause). Mid-task exhaustion stays governed by the Leader's existing wind-down protocol — mid-loop is exactly where a reset destroys working state, and recommending at the gate is the cheap version of the decision wind-down makes expensively later. Canonical doctrine in `docs/flow.md` → *Context Discipline*, including the host rule: name other hosts' equivalents only when confirmed, never by guessing. *"Necesito una app para vender carros"* leaves the product shape itself undecided — C2C marketplace, dealer inventory platform, and classifieds are three different products from that sentence — and the constitution's Brand-new mode had no protocol for it: the interview-guide machinery existed but was unbounded in one direction (question fatigue) and unguarded in the other (fabricate everything, and Step 9's single approval rubber-stamps it). The second failure is the dangerous one, because **everything downstream treats the PRD as constitution — a fabricated PRD is not a draft, it is a false constitution that specify/execute will faithfully obey.** New thin-seed protocol in Step 2: **(1)** sufficiency check across five dimensions (users/product shape, core v1 flows, success/monetization, stack, hard constraints; thin = ≥2 undecided); **(2)** exactly **one** bounded clarification round — ≤7 batched questions, each carrying a proposed default so the user can veto in a word, answer partially, or say "decide tú"; no second round unless answers contradict; **(3)** everything the user did not decide lands as a **labeled Assumption** (Hypothesis Template) — never woven into prose as settled fact — and Step 9 lists decided vs assumed distinctly; **(4)** a thin seed yields a thin PRD honestly: MVP-scoped with open questions, because acknowledged uncertainty gets resolved next cycle while fabricated specificity gets *built*. Echoed in `docs/flow.md`'s Day 1 section.
- **The day-1 handoff out of the constitution is now explicit — you never re-propose the seed prompt.** On a brand-new platform, the seed prompt drives `/akili-constitution` (PRD, UX/UI, TRD, infrastructure) and then… the methodology went silent: nothing said what to do next, and the natural-but-wrong move is feeding the seed prompt to `/akili-propose`, which would duplicate intent that already went through the constitution's review gate into a `proposal.md`. Three fixes: **(1)** `/akili-constitution` Step 9 now closes with the next step **by mode** — Brand-new: propose-as-decomposition or straight to specify; Legacy: propose or audit-first; Active: resume — because the handoff is where new users get lost, and "baseline created" is not an ending. **(2)** `/akili-propose` gains a **Greenfield track**: fresh constitution + no application code → the PRD is the approved intent; don't ask the user to restate it; the proposal's job becomes decomposing the v1 scope into bounded changes via the existing Scope Chunking mechanics (RICE/MoSCoW build order), each proposal *referencing* PRD sections and owning only the slice boundary (what this chunk delivers, defers, and depends on); a v1 that is genuinely one bounded piece skips to `/akili-specify`. **(3)** `docs/flow.md` gets a *Day 1 on a Brand-New Project* section with the full seed → constitution → chunked proposals → per-chunk specify/execute sequence, linked from README's Start Here. The proposal layer earns its cost when the MVP needs chunking and ordering — never as a re-statement ritual.
