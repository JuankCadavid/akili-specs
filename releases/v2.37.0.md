# v2.37.0 - AKILI-SPECS methodology update

Release date: 2026-10-26

### Added

- **`/akili-review` reviews a pull request, a commit range or the staged changes against its specs, anytime and outside the spec lifecycle.** Usage: `/akili-review [<pr> | <base>..<head> | --staged] [--spec <path>] [--tier auto|trivial|lite|full] [--lens <a,b>] [--comment] [--ci [--input <dir>]] [--fail-on none|critical|warning] [--record] [--force] [--out <dir>]`. It filters and tiers the diff, runs one lens reviewer per lens and chunk, verifies the findings and writes `findings.json` and `REVIEW.md` to a run directory outside the target (`~/.akili/reviews/...`). It has no Approval Mode and a read-only boundary: it never edits target source, runs target code, commits, pushes, approves a PR or requests changes.
- **Posting is gated and goes only through the packaged scripts.** Without `--comment` nothing is posted; with it, `post-review.cjs post --dry-run --local` shows the summary and the inline list, and the command stops for Post, Edit selection or Cancel. The script creates or updates one summary comment and posts at most 10 inline comments as one review whose event is always `COMMENT`. `--fail-on` defaults to `none`; the label `akili-review:advisory` forces `none` and the label `akili-review:skip` skips the run. `check-skip` also skips a draft, closed or merged PR, a bot author and a head that already has a review (`--force` overrides the last two).
- **Risk tiers and lenses come from the `prepare` script, not from the model.** `trivial` (at most 10 changed lines) runs `spec` and `correctness`; `lite` (at most 100 lines and 20 files) adds `tests`; `full` adds `maintainability` and `security`, and `docs` when a kept file is documentation. A security-sensitive path forces `full` and adds a `/akili-security <paths> --profile quick` recommendation, which the command never runs. Criticals are verified by tier: two blind judges in `full`, one verifier in `lite`, none in `trivial`. With no sub-agents every critical becomes a `suspect` warning and never counts toward `--fail-on critical`. The confidence threshold defaults to 80.
- **The packaged `pr-review` skill (binding `core`) carries the method.** It ships `validate-review.cjs` (exit 0 valid, 1 invalid, 2 usage), `post-review.cjs` (`prepare`, `check-skip`, `render`, `post`), `review-schema.json`, three references (`lenses.md`, `large-prs.md`, `ci.md`) and a `NOTICE`. The lens text is rewritten in AKILI's own words from two permissively licensed upstream works (Apache-2.0 and MIT), credited with their pinned commits in `NOTICE`; no file is adapted from an all-rights-reserved work. `judgment-day` gains a row for the `/akili-review` blind-judge use.
- **CI templates under `docs/ci/`:** `akili-review.claude.yml` (`anthropics/claude-code-action`, secret `ANTHROPIC_API_KEY`), `akili-review.codex.yml` (`openai/codex-action`, secret `OPENAI_API_KEY`) and `docs/ci/README.md`. Each has a read-only `review` job that checks out the PR base and a separate `post` job that holds the only write token, takes repo, PR and SHAs from the event and posts. Draft and fork pull requests are skipped, and the templates pin the `akili-specs` release that ships `/akili-review`. The README covers setup, the pilot-then-enforce path, the trust boundary and the residual risk.
- **Docs.** New `docs/commands/akili-review.md` and `docs/skills/pr-review.md`; `README.md`, `docs/README.md`, `docs/commands/README.md`, `docs/overview.md`, `docs/flow.md` (new section 2d, an artifacts row, "Seven anytime commands"), `docs/skills/README.md`, the `core` row of `docs/skills/governance.md` and the `AGENTS.md` Skill Usage list name the command and the skill.

### Changed

- **`reviews/` joins the non-spec carve-outs under `docs/specs/`.** `/akili-audit`, `/akili-propose`, `/akili-resume` and `/akili-specify` (and the `docs/commands/` pages for `/akili-audit` and `/akili-resume`) list it with `archive/`, `general-setup/`, `quick/`, `kaizen/` and `audits/`, so the opt-in `/akili-review` history (`--record`) is never read as a spec.
- **Docs and tests count 14 commands and 29 packaged skills, up from 13 and 28.** `docs/cli.md` carries the new totals (the `--commands-only` row, both install-layout listings, the shared-root sentence and the Grok Bot paragraph). `test/install-cursor.test.js` moves its packaged skill file count from 236 to 244 and its totals to 14 commands and 29 skill directories, `test/fixtures/doctor-codex-baseline.txt` moves from `ok 49` to `ok 51`, and `test/diagram-design.test.js` and `test/akili-marketing-docs.test.js` follow the new totals.

### Notes

- **Release class: minor** (a new command and a new skill).
- **Tests.** Five new files: `test/pr-review-scripts.test.js` (167), `test/pr-review-scripts-coverage.test.js` (13), `test/akili-review-command.test.js` (33), `test/akili-review-contract-coverage.test.js` (20) and `test/akili-review-ci.test.js` (30), with fixtures under `test/fixtures/pr-review/`. The whole suite is 1108 tests, all passing on Node 18.20.8 and on Node 22.23.3 on macOS.
- **Known limits.** The CI `review` job downloads the PR head tarball with a read-only token; whether that works on private repositories is unverified until the pilot, and it fails closed. `gh pr diff` can refuse a very large diff, and the job then fails instead of reviewing. A pull request is untrusted text: a prompt injection cannot post, fetch or run anything, but it can skew what the agent reports.
- `/akili-review` changes nothing in `bin/`, `package.json` or `package-lock.json`. There is no `/akili-review` row in the model-routing registry; the command carries a one-line model checkpoint instead.
