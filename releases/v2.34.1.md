# v2.34.1 - AKILI-SPECS methodology update

Release date: 2026-10-19

> This release (classified **patch**: a bug fix and corrections to the `/akili-security` command and its docs; no new command or skill) integrates two archived specs: `bugfix/update-check-deadline` and `changes/akili-security-followup`, plus the Kaizen Apply Mode pass of 2026-10-19.

### Changed

- **`/akili-security` Step 0.1 checks the pinned commit literal, and a foreign copy gets a restore offer (`changes/akili-security-followup`).** The preflight now requires the loaded `security-audit` copy's `source` to name `c1c8a8c1471069fb0e188eeaff69b8e8db6564a8`; a `source` naming any other commit (a copy from `npx skills add`, or an AKILI copy from before a re-sync) makes the copy foreign. The offer is **continue with that copy**, **restore the pinned copy**, or **stop**; it replaces the old `akili install --force` offer, and `--force`, an `npx` command or any command that overwrites installed files or fetches from the network is never offered. **Restore** moves the skills-root entry (the symlink itself, never its target) to a fresh `~/security-audit-skill/foreign-copy-<YYYY-MM-DD>-<n>/`, then re-runs the owning `akili install` with `--skills-only` and without `--force`. It is offered only when the entry or its resolved path, and the destination, are each neither inside the target nor an ancestor of it; otherwise only **continue** and **stop** are offered and nothing inside the target moves. After a restore whose install exited 0 the command ends before the plan gate and tells the user to re-run `/akili-security` in a fresh session; when the install exits non-zero it reports the exit code and where the moved entry now is, then ends. The pin is also checked by a new test that fails when the command's Step 0.1 literal, `SKILL.md` `source` and `UPSTREAM_SHA` name different commits.
- **The preflight reads the source ref as data: no git command before Run and none in Steps 4 and 5.** A hostile `.git/config` can launch a program (`core.fsmonitor`) from any git command, so Step 0.3 no longer runs `git status --porcelain`. The branch and commit come from `HEAD` and the ref files: `.git` must be a real directory (a symlink, or a file such as a linked worktree or submodule, reads `not determined`); a file is read only when it is a regular file within 64 KiB (`packed-refs` 1 MiB) whose fully resolved path is inside `<target>/.git`, and no file or directory on the path is a symlink; a commit is admitted only as 40 or 64 lower-case hex characters and a branch name only in `[A-Za-z0-9._/-]` with no `..` component. The dirty state is asked of the user at the plan gate. A commit or dirty state that cannot be read or confirmed is recorded as `not determined` in the plan, `run-metadata.json` and the index, never as clean. This is narrower than "no git during an audit": after **Run**, the skill's own phases and delegated agents may still run git in the target (accepted risk R-A, recorded for a later proposal).
- **The run directory is always outside the target.** An ignored directory inside the target is no longer accepted: ignore state is not consulted, and a run directory is refused when its real path (symlinks resolved) is inside the target or contains it, which refuses `--out /`, a parent of the target, or a default that falls inside the target because HOME does. `README.md`, `docs/flow.md` and the command pages say "always outside the target".
- **The execution gate quotes upstream's controls and exposure rule verbatim.** The sandbox the user confirms must be "an OS-enforced sandbox that provides all of these controls" (skill, *Universal execution safety*), with upstream's four bullets quoted verbatim and the skill's exposure rule ("Never expose a retained output directory …") required of the mechanism; the previous paraphrase ("all four controls") is gone. The delegated agents' brief addendum has a mechanism slot, `sandboxed-approved via <mechanism>`, filled from what the user named at the gate; `static-only` names none.
- **The index records the skill copy and `not determined`, and names the run path in two forms.** The header gains `Skill copy`: `pinned`, or `foreign — continued by <approver>` (the approver as named at the gate, default "the user"), and never the copy's resolved path. The source ref shows `not determined` for a commit or dirty state that did not resolve. The run path is `~/…` (under HOME) or `<external>/run-<N>` (anywhere else); the repo-relative form is removed with the in-target directories. The index filename's branch suffix comes from the branch Step 0.3 read from `HEAD`, through the `$SAFE_NAME` rule (`/` becomes `--`), never from a git command or `/akili-audit`'s resolution; it is omitted when the branch reads `not determined` (a detached `HEAD` included), and added when the branch is not the pinned default branch or no pin exists.
- **Routed slugs carry the run number: `bugfix/security-<YYYY-MM-DD>-r<N>-s<n>`.** `<N>` is the `N` of `run-<N>`, so two runs on one date print `-r1-s1` and `-r2-s1` for the same `S-1` and no longer collide. The slug is still built only from the run date, `N` and the `S-n` id, charset `[a-z0-9-]`. The `security-audit` skill's routing row, `README.md`, `docs/flow.md`, `docs/commands/akili-security.md` and the skill page carry the new form.
- **The skill docs gain a Windows gate step and the provenance limit.** `docs/skills/security-audit.md` re-sync procedure step 5 keeps the Windows preflight stop and test branch unless a candidate branch that removes the `win32` short-circuit passes the non-fallback cases on both Windows CI legs (Node 18 and 22); a wrapper, shim or patch to a vendored file never substitutes for it. The page also states that the provenance check is necessary but not sufficient: a hostile copy can forge `adapted-for` and `source`, so a matching pin neither proves that the body is the vendored one nor waives the command's other gates (R-B). Step 4 of the procedure now lists the command's Step 0.1 pin among the pin sites.
- **The command's closing checklist follows the changes.** FR-2 names the pin literal, the restore without `--force` and the command ending after a restore; a new item states that no git command ran in the target before **Run** or in Steps 4 and 5; FR-4, FR-6, FR-8 and FR-10 restate the quoted controls, the outside-target run directory, the two location forms with the skill copy and `not determined`, and the `-r<N>` slug.

- **Reviewer persona: a prohibition is checked through cross-references (Kaizen, `changes/akili-security-followup`).** `.claude/templates/reviewer.md` *Requirement Conformance* gains one line: when a requirement forbids an action in named steps, a grep for the action is not the check — the Reviewer follows every cross-reference out of those steps and confirms the referenced procedure does not perform it.

### Fixed

- **The update check could hang on a registry that trickles bytes (`bugfix/update-check-deadline`).** `fetchLatestVersion` bounded only idle time (`timeout: 1500` is re-armed by every received byte), so a response of one byte per second never settled `akili check-update` (the SessionStart hook command) or the interactive startup check. It now gives up after an overall 3 s deadline (`UPDATE_CHECK_DEADLINE_MS`) that destroys the request, and `res.on("error")` is attached before the status check. The result, the 24 h cache and the output are unchanged; a failed check still writes no cache. Regression test: `test/update-check.test.js` (slow drip, 404 cut, 200 cut, healthy control) through the `test/fixtures/update-check/registry-redirect.js` preload.

### Notes

- **An upstream request for the Windows validator limit is drafted and not filed.** `docs/specs/archive/2026-10-19-changes--akili-security-followup/upstream-request.md` is a draft for the maintainer to file against `cloudflare/security-audit-skill`; it is not filed and not part of the npm package (`docs/specs` is excluded from it). `docs/skills/security-audit.md` points to it.
- **Tests.** `test/akili-security-command.test.js` goes from 61 to 89 cases and `test/security-audit-skill.test.js` from 6 to 7; they pin the pin literal and the three-way pin sync, the restore offer and its conditions, the verbatim controls, the no-git rule and the ref-reading rules, the two location forms, `not determined`, the slug on both sites and the checklist items. A new `test/akili-security-docs.test.js` (19 cases) pins the restatements in `README.md`, `docs/flow.md`, the command and skill pages and `SKILL.md`'s routing row: the `-r<N>-s<n>` slug, no in-target run directory, the verbatim controls and exposure rule, the restore containment terms, no git instruction, the Step 0.1 pin in the re-sync procedure, the Windows gate step and the R-B limit. `npm test` passes 408 cases on the spec branch; 413 with `bugfix/update-check-deadline` integrated.
- `changes/akili-security-followup` changes nothing in `bin/`, `package.json`, `docs/model-routing.md`, `.claude/templates/` or any vendored `security-audit` file other than the `SKILL.md` routing row; in this release `bin/akili.js` changes only through `bugfix/update-check-deadline` and `.claude/templates/reviewer.md` only through the Kaizen line above.
