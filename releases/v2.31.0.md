# v2.31.0 - AKILI-SPECS methodology update

Release date: 2026-10-01

### Added

- **Cursor joins Claude Code, OpenCode, Google Antigravity, and OpenAI Codex CLI as a fifth install target (release classified minor: new install target, `changes/cursor-install-target`).** `akili install --tool cursor` writes the 11 commands and 24 packaged skills as Agent Skills under the same shared `~/.agents/skills` root Codex already uses (`--tool all` writes it once; a second install from either tool skips it), and resources (personas, scripts, `.mcp.json.example`) under `$CURSOR_CONFIG_DIR/akili` if set, else `~/.cursor/akili`; `--cursor-target` moves the resources root, `--cursor-skills-target` moves the skills root independently, and `--target` with `--tool cursor` selects the same single-root sandbox layout Codex gets. `--tool all` now means Claude Code, OpenCode, Antigravity, Codex, and Cursor in that order; `--tool both` is unchanged (Claude + OpenCode). `init`'s wizard gains `5) Cursor`, renumbering the combos to `6) Both` / `7) All five` — inputs `5` and `6` change meaning from the previous release, where `5` was Both and `6` was All four. Auto-detection keys on Cursor's own resources root, symmetrically with Codex: a shared, foreign-only `~/.agents/skills` evidences neither tool; an `akili-<cmd>/SKILL.md` command skill evidences Codex only while no sibling tenant's resources root is populated; Cursor's own resources root evidences Cursor only, suppressing the command-skill signal for Codex; and both resources roots present evidences both. `doctor --tool cursor` checks every command skill, packaged skill, and resource file on a fresh install and gains a `cursor-agent` Environment row (probes the `cursor-agent` binary, names the `agent` alias and both install commands, never failing the health check).

- **`/akili-constitution` Steps 7, 8C, 8E, 8F, and 9 gain Cursor guidance.** Step 7 adds the Cursor template-source line. Step 8C's `## Model Routing` registry gains a Cursor column (tier families, not slugs — Cursor's roster is multi-vendor) and a CLI-invocation row (`agent`; commands invoked as skills with `/akili-<name>`). Step 8E offers `.cursor/agents/akili-{leader,implementer,reviewer,tester}.md` wrappers — thin Markdown referencing `.agents/<role>.md`, `model` from the registry's Cursor column with an optional `[effort=<rung>]` bracket, and the Reviewer wrapper alone carrying `readonly: true` as the write-axis half of author ≠ auditor; `.cursor/agents/` takes precedence over same-named `.claude/` or `.codex/` wrappers. Step 8F's guardrail hook script gains a Cursor host row: Cursor maps `Edit` to `Write` on import, so the script's `Write` arm now reads the new-content field as `.tool_input.content` (the pre-existing Claude Code field) **then** falls back to `.tool_input.new_content`, and denies fail-closed when a `tasks.md` write carries no readable new content (neither `.tool_input.content` nor `.tool_input.new_content`, or an empty one) — closing the silent-allow gap the two new red fixtures (`new_content`-only, neither-field) exercised. On Cursor, the step writes the imported `.claude/settings.json` entry first (on by default via Cursor's *Include Third-Party Plugins* setting), asks the user whether that setting is on, and merges a native `.cursor/hooks.json` entry with `failClosed: true` only when the answer is off or unknown. Step 9's summary and the Verification Checklist name all five hosts. Honesty, stated plainly rather than overclaimed: the gate is **enforced** on Claude Code and Codex, **instructional** on OpenCode and Antigravity, and **enforced on the Cursor CLI** — observed live 2026-10-01 (cursor-agent 2026.09.26→2026.10.01, headless `agent -p`): the **imported** `.claude/settings.json` hook denied a `[x]` write without PASS and allowed it with PASS (empty-stdout `exit 0`, fail-open semantics); the payload's new-content field is `content` and carries the whole file; the hook ran from the project root; a `readonly: true` subagent could neither write nor run shell commands — the **Cursor IDE** half of the validation was deferred and stays `UNVERIFIED — confirm at source before relying on it`. A follow-up live finding (cursor-agent 2026.10.01-14929f9): on a **native `.cursor/hooks.json` entry with `failClosed: true`**, that same empty stdout is a hook *failure*, not an allow, and blocked the with-PASS write ("…returned no output"). The script now emits `{"permission":"allow"}` on every allow terminal when the payload carries a Cursor-only marker (`cursor_version`) — re-observed **allowed** on the native entry after the fix, with the without-PASS write still denied unaffected; Claude Code and Codex payloads (no `cursor_version`) keep receiving empty stdout exactly as before.

- **Per-host guidance in `/akili-execute`, `/akili-test`, and `docs/flow.md` names Cursor everywhere it names a host.** Both commands gain a Cursor spawn-mechanics bullet (named `.cursor/agents/` subagent invocation via the Task tool, batched-message parallelism); `/akili-execute`'s bullet alone also states the depth-2 subagent limit. Their model-checkpoint wording adds `/model` in the Cursor `agent` CLI (the IDE's model picker is `UNVERIFIED — confirm at source before relying on it`). Unattended Mode states no verified equivalent for Cursor, the same as Codex — its `goal`/`loop`/`autopilot` built-ins are observed to exist, but no cited source documents one evaluating a condition and looping. `docs/model-routing.md` gains a Cursor column across all six capability tiers, an *Enforced routing* row for the Markdown wrapper, an effort-mapping note, and an `agent`/`/akili-<name>` invocation row.

- **Documentation aligned to five supported hosts.** Mirrors (`docs/commands/*.md`, `docs/cli.md`) and root docs (`README.md`, `docs/README.md`, `.claude/README.md`, `AGENTS.md`, `CONTRIBUTING.md`) now say five wherever they said four. `docs/cli.md` documents the Codex + Cursor shared `~/.agents/skills` root and Cursor's separate compatibility reads of `~/.claude/skills` and `~/.codex/skills` in one new section, and its interactive-init numbering, `--tool`/`--cursor-target`/`--cursor-skills-target` rows, install-target layout block, four-state detection fixture, and `cursor-agent` doctor row all move in step with the installer. A closure sweep (`git grep` over the four-host enumeration patterns) ran before and after this batch of edits; every surviving hit is either an updated host-count sentence, a frozen historical release note, or a recorded non-host count (persona counts, review-intensity conditions, env-var counts) — never a silent gap.

- **New tests:** `test/install-cursor.test.js` (layout identity vs. Codex at the directory and file level, skip-on-second-install, the four detection states, `--dry-run`/partial installs, `doctor --tool codex` output unchanged against a pre-change baseline) and `test/tasks-gate.test.js` (the Step 8F gate script's fixtures, extracted from the constitution's fenced block, including the three new Cursor `Write` fixtures and the pre-existing Claude Code `Edit` / Codex `apply_patch` fixtures, unaffected); `scripts/ci/install-layout-regression.js` gains the four-state shared-root detection fixture, pinning `CURSOR_CONFIG_DIR` and `CODEX_HOME` to the scratch home.
