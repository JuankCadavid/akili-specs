# v2.19.1 - AKILI-SPECS methodology update

Release date: 2026-07-28

### Changed

- **Every duplicated rule between the Leader persona and its commands now has exactly one home.** `leader.md` and `/akili-execute` are loaded into the *same context* on every run, and several rules lived fully written in both — some in three places, since `/akili-test` carried its own copy of the skill/effort ownership rules. Duplication in co-loaded documents is paid twice per run forever, and worse, it drifts: three of the pairs had already started diverging this session (the Attempt History rule existed only in the persona; the `Not Done / Assumptions` gate existed only in the persona; the wind-down text differed in emphasis). The split is now principled: **judgment is canonical in `leader.md`** (skill/effort ownership, delegation thresholds/ceiling, cross-host rules, winding down, concurrency — the sections that serve both commands), **mechanics are canonical in the command** (spawn payloads, loop pseudocode, finalize order, HALT format). Concretely: the persona's *Orchestration Sequence* section (a pure restatement of command Steps 1–4) is gone, its two unique rules relocated — `Not Done / Assumptions` became `/akili-execute` Step 2.3.0 (**a task with an outstanding gap never reaches `[x]`, even on a Reviewer PASS** — the Reviewer audits what was written, not what was omitted), and Attempt History joined the rework-feedback brief item; the persona's rework/traceability/constitution-impact instructions compressed to pointers at the command's operational steps; the command's skill/effort brief items and wind-down guardrail compressed to pointers at the persona's canonical sections; `/akili-test`'s third copy of the ownership rules now defers to the persona, keeping only its suite-specific flavor. Net: ~700 tokens less persona re-read per run, and — the durable part — no rule left that can silently fork.
- **`/akili-execute` Step 0 no longer reads `docs/specs/general-setup/`.** Those files are the *format templates* `/akili-specify` authors specs from; by the time execute runs, the spec documents are already written, and the execution log's own format is defined inside the command. The executor consumes specs — it never authors them. Every other reader keeps it legitimately: specify (format source), seo/validate (report templates), archive (Kaizen's Standardize step proposes edits to those templates). The dropped read was paid on every run of every spec for zero consumption, and the list now says explicitly why the path is absent, so a future edit does not "helpfully" restore it.
