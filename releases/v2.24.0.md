# v2.24.0 - AKILI-SPECS methodology update

Release date: 2026-09-17

### Added

- **OpenAI Codex CLI joins Claude Code, OpenCode, and Google Antigravity as a fourth install target (release classified minor: new install target and new command capability, `changes/codex-install-target`).** `akili install --tool codex` writes the 11 commands as Agent Skills (`<skills-root>/akili-<name>/SKILL.md`, invoked `$akili-<name>` — never a `commands/` directory), the 24 packaged skills with their `references/` trees, and resources (personas, scripts, `.mcp.json.example`) under `<config-home>/akili`. Codex is the first target whose skills root sits outside its own config home (default `~/.agents/skills`, shared with any other tool honoring the Agent Skills standard) and independent of its resources root (default `~/.codex/akili`): `--codex-target` moves the resources root, `--codex-skills-target` moves the skills root, and `--target` with `--tool codex` selects a **single-root sandbox layout** (`<path>/akili` + `<path>/skills`) that fully isolates a temp/CI install (and, pointed at `~/.codex`, produces a working legacy-style install, since Codex still reads `~/.codex/skills`). `--tool all` now means Claude Code, OpenCode, Antigravity, and Codex in that order; `--tool both` is unchanged (Claude + OpenCode); the multi-tool verify hint prints `--tool all` only when all four were installed, `--tool both` only for that pair, and one `--tool <t>` line per tool otherwise. `doctor --tool codex` checks every command skill, packaged skill, and resource file, gains a `codex` Environment row (`codex --version`, never failing the health check), and prints one informational line — never a deletion — when an old manual `~/.codex/skills/akili-*` copy exists alongside a complete standard install. Auto-detection keys on the resources root or on an `akili-<cmd>/SKILL.md` command skill, **never** on a populated shared skills directory alone, so a foreign-only `~/.agents/skills` is never misread as a Codex install; `init`'s wizard gains `4) OpenAI Codex CLI`, renumbering the combos to `5) Both` / `6) All four`. The installer's `TOOL_REGISTRY` is generalized from three ad-hoc entries to per-type roots plus two capability flags (`commandsAsSkills`, `sharedSkillsRoot`) — Antigravity's command-as-skill behavior is now expressed through the same flag instead of a hardcoded `tool === "antigravity"` branch, which is deleted from both the install path and the `doctor --fix` restore path (`grep -c 'tool === "antigravity"' bin/akili.js` is now 0).

- **Codex's config home follows `$CODEX_HOME` when set, falling back to `~/.codex`** (T7 finding, resolved as a bounded T1 delta): `defaultPaths.codex`, auto-detection, and the doctor's legacy-copy line all resolve from the same value, so they stay consistent with whichever config home Codex itself is using. Global default only — `--local` still resolves to `./.codex`, and `--codex-target`/`--target` still override outright. The CI regression fixture pins `CODEX_HOME` to its own scratch home so an inherited value from the runner's shell can't mask a false positive in the detection check.

- **A layout-identity install-layout regression gate protects the three existing targets while the shared command files change underneath them.** New `scripts/ci/install-layout-regression.js` (Node, no deps, Windows-safe) installs the **published** `akili-specs@2.23.2` into an isolated `npm install --prefix <tmp>` sandbox (invoking that sandbox's own extracted `bin/akili.js` directly — never `npx`, which resolves by bin name and exits 127 on a cold runner since the package's bin is `akili`, not `akili-specs`) and the working tree into separate temp roots for `claude`, `opencode`, and `antigravity`, then compares sorted relative file lists (must match exactly — the layout-identity leg) and per-file SHA-256 (a content difference is tolerated **only** when the working tree's file is byte-identical to its own current source under `.claude/` — printed `EXPECTED-DIFF <tool> <path>` — because this spec's own Codex paragraphs land in those shared files). It reads the published side's resolved version from the sandbox's own installed `package.json` to guard against a false pass from a shadowed local install, and runs the FR-1 auto-detection fixture (a foreign-only shared skills root must not detect Codex; adding one command skill must) in-process. The step is added to every CI matrix leg (ubuntu/macos/windows × Node 18/22) after the existing symlink-defense probe, and **skips** (`SKIP: registry unreachable (<reason>)`, exit 0) only on npm registry failure — a real install failure still fails the job. `docs/cli.md` documents the rule in a new *CI & Verification* section.

- **The methodology's per-host guidance now names Codex everywhere it names a host.** `/akili-constitution` Step 8C scaffolds a fourth registry column and CLI-invocation row (`agy` for Antigravity, `codex` for Codex — both easy to guess wrong); Step 8E offers `.codex/agents/akili-{leader,implementer,reviewer,tester}.toml` wrappers (`developer_instructions` referencing, never duplicating, the `.agents/<role>.md` persona; `model` from the registry; `model_reasoning_effort` per role; the Reviewer wrapper alone carrying `sandbox_mode = "read-only"` as the write-axis half of author ≠ auditor, since Codex has no documented per-agent tool allowlist) and documents the `.agents/` three-tenant layout (personas / Antigravity wrappers under `.agents/agents/` / Codex repo-scope skills under `.agents/skills/`) so the same directory name never collides across hosts; Step 8F extends the `[x]`-without-PASS-evidence guardrail hook to Codex's `.codex/hooks.json` (`PreToolUse`, same merge and fail-closed discipline as the Claude Code hook, sharing one script when both exist) and drops "Claude Code only" from its title — the gate is now **enforced** on Claude Code and Codex, **instructional** on OpenCode and Antigravity; Step 9's summary and the Verification Checklist name all four hosts and, for Codex projects only, add a one-line `AGENTS.md` byte-size check naming `project_doc_max_bytes` as the `config.toml` key to raise. `/akili-execute` and `/akili-test` gain a Codex spawn-mechanics bullet (the Leader requests a named role and Codex itself spawns, routes, and returns the result — documented as model-driven orchestration, not a tool contract) and their model-checkpoint wording adds Codex's `/model` command; `docs/flow.md` adds the Codex tenant to its `.agents/` resolution paragraph and states no claim for Codex's launch/unattended equivalents. `docs/model-routing.md` gains a Codex column across all six capability tiers (family names — Astra, Sol, Terra, Luna — not dated slugs, per the same alias-first treatment as Antigravity), an *Enforced routing* row for the TOML wrapper, a `/model` bullet in *How to apply per tool*, and a `codex` CLI-invocation row.

### Fixed

- **The Codex install spec's own regression rule was self-contradictory and got corrected before it shipped (Pivot Record, `changes/codex-install-target` T2).** The original FR-4 wording ("nothing installed for Claude Code, OpenCode, or Antigravity changes byte-for-byte") could never hold once the very same spec's Step 8E/8F/8C/execute/test edits land in the shared command files every host installs identically — a literal implementation would fail CI on every future edit to those files, permanently. Amended, git-free, to **layout identity + source-equality tolerance**: the sorted file list must match exactly, and a content difference is only acceptable when the working tree's copy is byte-identical to its own current canonical source — an installer mapping bug still surfaces as a path difference or as a content diff that does *not* match its source.

### Deviations from the original proposal

- **No legacy cleanup of `~/.codex/skills/akili-*`.** The installer never wrote there, so any such files are the user's own manual copies; `doctor` may mention them, never delete them — consistent with the skip-by-default ethos the rest of the installer already follows.
- **`--target` with `--tool codex` is a single-root layout** (`<path>/akili` + `<path>/skills`), not a mirror of the split default — the only way to fully sandbox a Codex install under one temporary path.
- **Codex sets reasoning effort through `/model`, not a separate `/reasoning` command** — the pinned CLI reference states `/model` "choose[s] the active model (and reasoning effort, when available)" in one prompt; every command, docs mirror, and registry entry in this change uses that wording.

### Live validation (T7, resolved — codex-cli 0.154.0, 2026-09-17)

The `Unverified:` markers queued for T7 in `.claude/commands/akili-constitution.md`, `akili-execute.md`, `akili-test.md`, `docs/flow.md`, and `docs/model-routing.md` are now resolved in a real Codex CLI session. Confirmed live: a read-only session (`-s read-only`) asked to create a file was denied (`patch rejected: writing is blocked by read-only sandbox`) — the Reviewer wrapper sets the same `sandbox_mode = "read-only"` key, though the wrapper-level attempt itself was not exercised; the Leader's rollout calls a `spawn_agent` tool (`namespace: "collaboration"`, `agent_type` = the wrapper's `name`, `fork_turns: "all"`) — observed, undocumented API, not a cited contract; the raw `PreToolUse` payload's `apply_patch` carries no `file_path` field, an **absolute** path in its `*** Update File:` header, and top-level fields `session_id, turn_id, transcript_path, cwd, hook_event_name, model, permission_mode, tool_name, tool_input, tool_use_id`; denial is honored via stderr + exit 2 (the `permissionDecision` JSON form was not needed); `model_reasoning_effort` accepts all six rungs (`low`/`medium`/`high`/`xhigh`/`max`/`ultra`), so the AKILI dial now maps `max`→`max`; and Codex does not surface `.agents/<role>.md` as a skill (the three-tenant layout is collision-free). Codex's `/goal` "keeps the goal attached to the active chat while work continues" — a persistent target, not a condition-evaluated loop — so "no verified equivalent for unattended looping" is now a pinned claim rather than an open question. The `<CONFIRM SLUG>` cells for T4 and T6 stay: T7 gathered no context-window or vision-capability evidence for any Codex model.

**New live findings, not anticipated by the original design.** The Codex model roster is **plan-gated**: on a ChatGPT-account login only `gpt-5.6-terra` and `gpt-5.6-luna` were accepted, while `gpt-6-astra` and `gpt-5.6-sol` were rejected — so T1/T3 (Astra) and T2 (Sol) fall back to the Terra/Luna pairing on such accounts, with author ≠ auditor kept via Reviewer `gpt-5.6-terra` ≠ Implementer `gpt-5.6-luna` (**superseded above**: `changes/model-routing-cost-rebaseline` makes Terra/Luna the registry's default pair outright, not merely the plan-gated fallback). A scaffolded `.codex/hooks.json` entry is inert until the user trusts it via `/hooks` (or passes `--dangerously-bypass-hook-trust` to `codex exec`). Codex's default `workspace-write` sandbox protects `.git/`, so `/akili-execute` Step 3's commit needs an approval. Skill descriptions are shortened to fit Codex's skills context budget (DD-9), but all 35 AKILI skills stay visible under the truncation. A separate `CODEX_HOME` environment-override finding was escalated to the user at the closing gate and resolved as a bounded T1 delta in this release (config home follows `$CODEX_HOME`; CI fixture pins it).
