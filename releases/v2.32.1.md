# v2.32.1 - AKILI-SPECS methodology update

Release date: 2026-10-17

### Changed

- **`akili routing`'s two multi-select questions (hosts, then each host's models) take keyboard input on a capable terminal (release classified patch, `changes/routing-keyboard-select`).** `↑`/`↓` moves the cursor and wraps at both ends, `space` toggles the current row, `a` toggles all rows, and Enter confirms once at least one row is checked — an empty Enter shows a guidance line instead of closing the question. Ctrl-C aborts the question, restores the terminal, and exits the process with code `130`; nothing is written — in either form, on every supported Node; on Node ≥ 22.23 the comma form previously printed an `AbortError` stack trace and exited 1. The keyboard form is used only when all four hold: stdin is a TTY, raw mode is available (`setRawMode`), the prompt's output stream is a TTY (stderr under `--json`, else stdout), and `TERM` is not `dumb` (`canKeySelect`, `bin/akili.js`) — anywhere one of those fails, the comma-separated-numbers form runs as before — same prompts and exit codes, except the empty-reply error text below and Ctrl-C (`130` in either form); single-choice prompts (host CLI invocation, tier adjustments, confirmations) always stay typed. The comma form's empty-reply error now carries guidance: `nothing selected: type at least one number, e.g. 1,3` (`parseNumberList`, `bin/routing.js`). No new dependency is added — the keyboard path uses only the core `readline`/`tty` APIs; `package.json` still declares no `dependencies`. `docs/cli.md` → *Routing* documents the keys and the four-member fallback rule. The keyboard path is not exercised on Windows CI; the fallback is.
- **Kaizen standardizations from `changes/routing-keyboard-select` (methodology, dogfooding).** `/akili-specify` Premise Ledger gains citation rule **(f) Runtime-bound** — a `data-env` row about runtime behaviour names the runtime and version it was observed on and is verified on the CI matrix's newest member when the matrix spans versions; `/akili-execute`'s Budget Tripwire now compares at every task's finalize with running totals in the entry, not only at the closing summary. `AGENTS.md` notes that `test/routing-pty.test.js` needs `expect` (macOS, Linux CI step) and skips on Windows.
