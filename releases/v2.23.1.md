# v2.23.1 - AKILI-SPECS methodology update

Release date: 2026-08-22

### Changed

- **Branch-safe two-phase Kaizen and shared-file write discipline — methodology writes are now conflict-free by construction under parallel branches (release classified patch: user decision, `changes/branch-safe-kaizen` Document Control).** Prompted by a live merge where 11 of 12 conflicting files were methodology artifacts. One principle governs every lifecycle write: *on a spec branch, only write files unique to that branch; every shared-file edit happens on the default branch, serialized.* The `kaizen` skill splits into a **retrospective phase** that runs on any branch and writes one entry file per spec at `docs/specs/kaizen/<safe-spec-slug>.md` (metrics, lessons, `## Noted, not a lesson` signals, and typed pending items — `standardization`, `digest-update`, `guide-sync`, `factual-sweep`, `trd-adr`), and an **apply phase** that runs only on the default branch through the new standalone **Apply Mode** ("apply pending kaizen standardizations"), where the HITL menu fires, approved edits land, ADR numbers are allocated, and the `## Active Lessons` digest is refreshed. That apply phase is now the digest's **single writer**; the log's legacy `## Entries` section is frozen, never migrated. Standardize still presents its proposals on a spec branch — the gate moves the write, not the review. `/akili-archive` gates its agent-guide sync, factual-claims sweep, and TRD & ADR sync on the same Branch Context, records them as pending items on a spec branch, reports a third standardization state (`pending`), and auto-offers the backlog when it already runs on the default branch. `/akili-audit` writes one report per run at `docs/specs/audits/drift-<YYYY-MM-DD>[-<safe-branch>][-N].md`, ordered by the `Date of Audit` header rather than filesystem mtime, with legacy `docs/specs/drift-report.md` kept as a permanent read fallback it never modifies. `/akili-resume` surfaces the pending count and highest severity and names the Apply Mode invocation, staying read-only. `/akili-constitution` scaffolds `docs/specs/kaizen/` and `docs/specs/audits/`, pins `Default Branch: <name>` in the constitution summary as the primary source every branch test compares against, and states the write discipline there and in the packaged `leader.md`/`implementer.md` personas — with the exemption for files an approved `tasks.md` names as the spec's own deliverable. The four `docs/specs/` scan sites (`/akili-resume`, `/akili-propose`, `/akili-specify`, `/akili-audit`) carve out `archive/`, `general-setup/`, `quick/`, `kaizen/`, `audits/`, and family containers explicitly. Consumer read contracts are unchanged: `/akili-propose`, `/akili-specify`, `/akili-execute`, and `/akili-resume` still read only the `## Active Lessons` digest at its existing path and columns. Guidance only: no installer, hook, or new-command change — Apply Mode is an activation of the existing skill. Docs mirrors and root docs updated (`docs/commands/akili-archive.md` — also corrected to parity, its sync summary had predated the factual-claims sweep and the TRD/ADR sync entirely — `akili-audit.md`, `akili-resume.md`, `akili-constitution.md`, `docs/commands/README.md`, `docs/skills/kaizen.md`, `docs/skills/README.md`, `AGENTS.md`, `README.md`, `docs/README.md`, `docs/flow.md`).

  **Expected on upgrade:** projects with `.agents/` personas deployed before this release will show a **one-time structural persona-drift flag** in `/akili-audit` (Model Generation Drift, the `:59(c)` structural check) — the packaged templates now carry the write-discipline guardrail and the deployed personas do not. This is the check working as designed, not a defect. Clear it by running `/akili-constitution` in Safe Update mode, which appends the guardrail without overwriting customizations.

### Fixed

- **Installer: single-file copies are now atomic, closing the TOCTOU symlink window in `copySingleFile` (Sentinel finding, PRs #9–#20).** `bin/akili.js` gains `atomicCopyFileSync`, copying to a `crypto.randomBytes`-named temp file with `fs.constants.COPYFILE_EXCL` and atomically `renameSync`-ing over the destination, replacing the last raw `fs.copyFileSync` call site that ran after the `removeTargetSymlinks` check. Same pattern and severity reclassification (reported up to CRITICAL, realistically LOW — the attacker must already control the destination directory) as the 2026-08-05 `atomicWriteFileSync` hardening; also buys crash-safety for interrupted installs. The twelve duplicate Sentinel PRs carrying this fix were closed in favor of this commit.
