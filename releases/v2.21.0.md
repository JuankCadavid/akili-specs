# v2.21.0 - AKILI-SPECS methodology update

Release date: 2026-07-30

### Added

- **SDD + TDD + Kaizen: the `tdd` skill joins the pack (Matt Pocock, MIT — the first external candidate this week to pass the acceptance bar).** Evaluated alongside a clean-code skill that did not (a summary of the Uncle Bob book already covered by the Reviewer's 4R readability lens and the Implementer's craft rules, plus function-length quotas of the mechanical style the stack rejects). Pocock's skill is current, quota-free, and **agent-aware** — its "horizontal slicing" anti-pattern (*bulk tests verify imagined behavior*) names precisely the default LLM failure mode, and its vertical-slice tracer-bullet loop is discipline, not theory. The AKILI adaptation makes the triad click: the anti-tautological rule demands expected values from *"an independent source of truth — the spec"*, and in AKILI that source **already exists and is already HITL-approved** — the `requirements.md` Given/When/Then scenarios; the upstream "confirm seams with the user" question is pre-answered by `design.md`'s approved interfaces; `/akili-specify` Bug Mode's mandatory red-before-green regression test was already this discipline (the skill generalizes it to features); refactoring stays out of the loop exactly where the harness already puts it (Reviewer 4R + `simplify`); and `author ≠ tester` survives — TDD tests are the author's tracer bullets, `/akili-test`'s Testers remain the independent proof and cite existing TDD coverage instead of rewriting it. Binding `conditional`: **the Leader assigns it per task** (algorithms, business rules, contracts — never copy/styling/config), the same judgment lane as every other skill assignment. Adopted per governance with upstream `tests.md`/`mocking.md` verbatim, attribution intact, and a `docs/skills/tdd.md` entry.
- **Guardrail hooks enter the methodology — Step 8F scaffolds the first one: no `[x]` without PASS evidence, enforced by the harness.** Evaluating an auto-commit hook (davila7's `smart-commit`) settled the design question of what hooks belong in AKILI. That hook specifically is incompatible four ways — an auto-commit per Edit would **empty the working-tree diff the Reviewer audits** (silently killing the review pipeline), commit unreviewed rework attempts, defeat the HALT Automatic Rollback, and replace `[SPEC:...]` traceability with size-of-change narration. The generalizable rule it produced: **a hook may block a violation; it must never perform an action the methodology routes through judgment** — guardrails yes, actors never. `/akili-constitution` Step 8F now offers (opt-in, one question, same pattern as 8E) to scaffold `.claude/hooks/akili-tasks-gate.sh` plus a merged `PreToolUse` entry in the **project's** `.claude/settings.json` (committed — binds every teammate's session, which is the point): flipping any `docs/specs/*/tasks.md` task to `[x]` is blocked unless the same spec's `execution.md` exists and carries PASS evidence. This is the enforcement half of the evidence-first ordering shipped in 2.18.0 — that reorder is what makes the gate possible at all. Tested against 8 scenarios before shipping (block without execution.md, block without PASS, pass with PASS, `[~]` parking untouched, non-tasks files untouched, fresh all-`[ ]` specify Writes untouched, `[x]`→`[ ]` reverts untouched, Write-introducing-`[x]` blocked). Honest limits recorded in the step itself: the PASS check is a v1 heuristic (projects can harden to per-task-ID matching); hooks are Claude Code's mechanism, so the invariant stays instructional on OpenCode/Antigravity — the same cross-host asymmetry Step 8E documents; settings merge never clobbers existing hooks and stops on unparseable JSON. Step 9 and the Verification Checklist require the scaffolded/declined state to be named.
- **Test-infrastructure bootstrap has an owner — a missing test command is a STOP, not a Tester improvisation.** Comparing the harness against an external generalist test agent (davila7's `test-engineer` — evaluated and rejected: a 6,800-word strategist prescribing coverage pyramids inside the Tester slot would break scope discipline and violate the *No Coverage Theater* rule by design) exposed a real gap on our side: the whole pipeline assumes "the project's real test command" exists, and in a greenfield project's first spec it does not — no runner chosen, no config, no `test` script — leaving the Tester to pick a framework inside its inner loop, exactly the architectural decision that is not its to make. Now: `/akili-test` Phase 1 stops the affected suites and routes the work correctly (runner choice = TRD stack decision; scaffolding = a spec task with its own Implementer → Reviewer pass), proceeding normally with suites whose infrastructure exists; `tester.md` reports missing infrastructure as `FAIL`/`AUTOMATION_DEFERRED` instead of choosing; and **performance/load testing is explicitly named out of scope** of the four suite types — it enters through the TRD's NFR scenarios and a spec's own verification tasks — so its absence reads as a decision, not an oversight.
- **`/akili-seo` gains a Growth Strategy addendum — the audit diagnoses, this prescribes what to build.** Evaluated adopting the `seo-optimizer` skill from davila7/claude-code-templates (MIT): ~70% overlapped what `seo-audit` already covers with more depth, and part of the remainder was stale guidance the stack has already moved past (FID targets — replaced by INP in 2024, which `seo-audit` already uses; keyword-density and word-count prescriptions modern ranking systems treat as spam signals). Adopting wholesale would have lowered the quality bar and created trigger ambiguity with `seo-audit`. The genuinely complementary delta — the *strategy* topics an audit doesn't cover — was written fresh as Phase 4.1: keyword/topic strategy derived from evidence the audit already read (real GSC queries over guessed volume; topic clusters, never quotas), featured-snippet/answer-surface shaping that cross-references the Phase 2 GEO findings (the same 40–60-word answer blocks generative engines quote), and Local SEO (GBP completeness, `LocalBusiness` JSON-LD, NAP consistency, per-location pages minus templated duplicates). **Opt-in, and offered only when the audit surfaced content/visibility gaps** — a purely technical audit skips it entirely; every recommendation must cite audit evidence, never a generic checklist. Verification Checklist enforces the offered/declined/not-applicable state being named. Credit: the gap analysis was prompted by the davila7 skill, whose useful lenses were re-derived against current guidance rather than copied.

### Fixed

- **The update check now bounds what it reads from the registry and releases sockets on error paths** (PR #2, Jules/Sentinel — first external-tool PR into the repo). `fetchLatestVersion` capped its response at 50KB with `req.destroy()` on overflow (the real dist-tags payload is ~200 bytes, so the cap never fires in normal operation) and drains non-200 responses with `res.resume()` instead of leaving the socket held with unread data. Reported as MEDIUM; realistically LOW — exploiting it requires a compromised registry or a MITM already past TLS — but the pattern (bound every external read, release every error-path socket) is the right default for any external data consumption, and the fix costs nothing. Line-by-line reviewed per CONTRIBUTING's installer rule; the possible double-`resolve` after destroy is a benign no-op, same as the pre-existing timeout handler. This entry and the `.jules/sentinel.md` date fix (2024 → 2026) are the follow-up the merge deferred.
