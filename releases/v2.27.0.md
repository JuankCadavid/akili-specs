# v2.27.0 - AKILI-SPECS methodology update

Release date: 2026-09-20

### Added

- **Review intensity — a conformance Reviewer becomes conditional on an earned falsifier (`changes/review-intensity-routing`).** `/akili-execute` Step 2.3 gains a **Review intensity** block: a task may close without an independent Reviewer only when its `Falsifier` executed against the post-change code and the gate observed red, every Verification check is fully deterministic, its `Consumers` field reads `none`, and none of seven overrides applies — evaluated against the Implementer's actual report, never against the task's plan. The evidence re-run — mechanical re-execution of the task's verification by a non-author context, never an audit of conformance — now runs on **every** task, whatever Review intensity decides, and is never waived; a mismatch is an implicit FAIL. Closure gains a third state, `REVIEW_SKIPPED`, a sibling of `REVIEW_WAIVED` and never merged with it: a skip is a gate the predicate proved was never owed, a waiver is a gate that was owed and lost. `/akili-specify` Step 3.2 adds a `Review` field (`skip-eligible` / `checklist` / `full` / `lenses`) with its own reason, surfaced in the Step 3.3 skip-eligible list at the approval gate and confirmed by a Verification Checklist item; a `tasks.md` written before this field exists behaves exactly as today (FR-10). The Implementer defaults to the registry's T2, with any escalation recorded like a skill deviation; the evidence re-run may run on the cheapest tier, T5, because it exercises no judgment. `kaizen`'s Measure table gains a skipped-task row and an escaped-defect row, and its clean-run predicate never classifies a run clean while a `REVIEW_SKIPPED` task carries an escaped defect against it. Mirrors (`docs/commands/akili-execute.md`, `akili-specify.md`, `akili-constitution.md`, `akili-resume.md`, `docs/skills/kaizen.md`), `docs/model-routing.md`, and `.claude/commands/akili-archive.md`'s Step 3 signal list brought to parity.

- **`AGENTS.md` is now the single canonical agent guide (`changes/agents-md-canonical`).** `/akili-constitution` scaffolds `## Model Routing` and `## Skill Map` into the project's root `AGENTS.md` **only** and no longer requires a parallel `CLAUDE.md`. The mirror existed because two hosts read two filenames; Claude Code now reads `AGENTS.md` directly, so one file serves both — **conditional on the other being absent**, which is what makes this an inversion rather than a deletion. With both files present Claude Code reads `CLAUDE.md` and ignores `AGENTS.md` entirely, so a `CLAUDE.md` that merely *names* the other file replaces the guide with a sentence about the guide: the command now states that a prose pointer is a **defect**, with the mechanism, and that the supported shim is an `@AGENTS.md` import with Claude-specific content below it. Symlinks are ruled out on two grounds (the Edit and Write tools refuse to write through them; a committed symlink checks out as plain text on Windows). The v2.1.277 version floor and the cases where `AGENTS.md` support is unavailable — Bedrock and other third-party providers, telemetry disabled, `disableAllHooks`, the first session after an install — are named, with the import as the route that keeps those projects readable. **Migration is additive: no existing `CLAUDE.md` is ever deleted.** This repository dogfoods it — its own `CLAUDE.md` is now the bare import.
- **Kaizen standardization from `changes/agents-md-canonical`.** `/akili-specify` Step 3.2 gains one task-quality rule: a removal or rename sweep is keyed on the **obligation**, not on the identifier being removed. A rule that mandates the thing you are deleting may never name it — *"written to both root guides"* survives every `grep` for the filename — and a heading-level inventory cannot see a bullet lost under a heading that survives in both files. Both failures happened in this spec, each costing a rework round.

### Fixed

- **The update check could hang the CLI when the registry connection dropped mid-response (#41).** `fetchLatestVersion` in `bin/akili.js` handled `error` and `timeout` on the request but not on the response stream. When a connection drops after headers, `res` emits `error` (`ECONNRESET`) while `req` emits only `close` — so the request's handler never fired and the promise never settled. Because `await checkForUpdates()` runs before every command, the CLI stopped responding. A `res.on("error", …)` handler now destroys the request and resolves `null`. Verified with a falsifier rather than a green run: with the handler stripped the reproduction hangs, with it in place the promise settles. Scripted and CI runs were never affected — the check returns early when stdout is not a TTY — and the 24-hour cache bounded it to at most once a day.

### Notes

- Proposed classification: **minor** — new methodology behavior (a conditional Reviewer, a new closure state, a new task field) that every consuming project can adopt without migration: a `tasks.md` without the `Review` field executes exactly as today, and no existing record, flag, or command is renamed or removed.
- Ships as a measured trial over the next 3 complete specs: every trial spec reports its `REVIEW_SKIPPED` count and escaped defects alongside the falsifier execution rate; one escaped defect against a skipped task reverts the change.
- The `AGENTS.md` change alters what `/akili-constitution` writes for **new and re-run** scaffolds. It is **not breaking**: no existing project's files are deleted or renamed, a project that keeps a `CLAUDE.md` keeps working, and consumers on a pre-v2.1.277 toolchain retain the `@AGENTS.md` import route.
- The `#41` fix is a user-visible bugfix in shipped CLI code and is release-worthy on its own; it does not change the **minor** classification above, which is driven by the methodology behavior.
