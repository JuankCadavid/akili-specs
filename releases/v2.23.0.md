# v2.23.0 - AKILI-SPECS methodology update

Release date: 2026-08-13

### Added

- **Kaizen standardizations from `changes/audit-phase-tier-drift` — three verification and dispatch rules (release classified minor: methodology behavior change).** `/akili-specify` Step 3.2 gains the **falsifying-input rule**: the existing disqualifier asks whether a *produced reading* is worthless, and this asks the prior question — could any input make the check report failure at all? A check chosen from the same frame as its claim cannot falsify it and reports green forever; the spec that produced this lesson hit that shape five times (a path evidenced only where it exists by construction, a byte-comparison that normalized both sides first, an authority cited for a fact it does not contain, a budget reported in the one unit under which it cannot be exceeded). Every verification must now name the concrete input that would produce a FAIL, or be recorded as a gap. `/akili-execute` Step 2.2's brief list gains **forward pointers recorded in `execution.md` against the task, copied and re-read when the brief is composed** — a branch deferred by an earlier Reviewer is not carried by having been filed. `.claude/templates/leader.md` corrects its own idle-worker claim: the brief line declaring the report the turn's terminating action is **not prevention** (measured across six spawns in one run, it failed twice on workers whose briefs carried it) — the protocol is **poke once, then replace on the second idle**. Guidance only: no installer, hook, or new-command change.

- **`family.md` spec-family manifest — parent→child order, dependencies, and status survive `/clear` (release classified minor: new methodology behavior).** `/akili-constitution` Step 7 defines `family.md` as a fourth general-setup template: Document Control plus an ordered child table (`Spec Path`, `Depends on`, `Parallel-safe`, `Status`) and the closed-set rule, authored only when a proposal is actually split — its absence means a spec is flat, with zero added obligations. `/akili-propose` and `/akili-specify` write the manifest at chunking time, before any child folder is created, and stamp each child's Document Control with `Parent Spec:`. `/akili-resume` reads every manifest before its flat directory scan, groups the dashboard by spec family, and recommends the next child by manifest order. `/akili-archive` flips a child's manifest row to `done` before the folder moves and blocks archiving a parent while any child is non-terminal. `docs/flow.md`'s fleet preconditions read independence, dependency, and merge order from the manifest instead of re-deriving them at dispatch time. Guidance only: no installer, hook, or new-command change. Docs mirrors updated (`docs/commands/akili-propose.md`, `akili-specify.md`, `akili-resume.md`, `akili-archive.md`, `akili-constitution.md`).

- **`/akili-audit` gains Phase→Tier Drift detection, plus a structural persona check that stops rotting on every future template change (release classified minor: new methodology behavior).** Prompted by a live case: a project's `/akili-execute` Leader ran on `haiku` for weeks while its registry, mirror, and Step 8E wrapper all agreed with each other — passing all five existing routing categories, because mutual consistency is not conformance. Step 2 gains a twelfth category comparing every phase→tier assignment in the project's `## Model Routing` registry against the packaged `docs/model-routing.md`, resolved by probing the packaged file (`node_modules/akili-specs/`, then `npm root -g` **and** `pnpm root -g`) and falling back to installed command files' own Model checkpoints (roots derived from `bin/akili.js`'s `TOOL_REGISTRY`, home and `--local` variants) before reporting the category **unevaluated** rather than silently skipped. Each finding cites the phase, local tier, packaged tier, and packaged rationale by file and line, High priority on T1/T3 phases. A project may silence a deliberate divergence with a fixed `> **Accepted divergence:**` marker in its registry — re-reported if the packaged tier it names later changes, never honored merely because a past audit stayed quiet. `:59(c)`'s guardrail check is now **structural**, comparing `.agents/*.md` against packaged templates under `akili/templates/` in the active tool's config root rather than a fixed two-item list, so a guardrail added upstream tomorrow is caught without being named in `akili-audit.md`; `leader.md`'s Delegation Ceiling and `implementer.md`'s Scope Discipline stay as worked examples, not the closed set. Step 3's Conformance Matrix gains a Methodology Conformance row carrying the Aligned/Drifted/Unevaluated state, so a clean phase is reported there and never as an informational entry in Identified Discrepancies. Report-only throughout: the audit never edits the registry, mirror, wrapper, or persona. Guidance only: no installer, hook, or new-command change. Docs mirror updated (`docs/commands/akili-audit.md`).

- **Unattended Mode guidance for `pre-approved` runs (release classified minor: a new documented capability).** `/akili-execute` Step 5 gains an Unattended Mode block, confined to the `pre-approved` context and to Claude Code, recommending `/goal` with a canonical condition template written once there: all tasks `[x]` with matching PASS evidence in `execution.md`, OR a HALT / Pivot Record / budget-tripwire block, OR a question pending for the user — plus a turn bound sized so it never fights the 3-attempt rework ceiling. The exception disjunction is part of the condition, not an add-on, so the loop cannot push past a human gate; the block also states the requirements (trusted workspace, unavailable under `disableAllHooks`, no change to tool permissions) and that no run ever depends on it. `docs/flow.md`'s fleet preconditions gain the per-host child launch they lacked — `claude -p "/goal <condition>"` in Claude Code referencing that one template, the goal plus exception contract in the dispatch brief for Google Antigravity, whose completion stays user-verified from artifacts with no platform-evaluated condition, and no claim for OpenCode. Every `/goal` claim is pinned to https://code.claude.com/docs/en/goal.md and every Antigravity claim to https://antigravity.google/blog/introducing-google-antigravity. Docs mirror updated (`docs/commands/akili-execute.md`). Guidance only: no installer, hook, or command change.
