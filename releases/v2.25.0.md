# v2.25.0 - AKILI-SPECS methodology update

Release date: 2026-09-19

### Added

- **Falsifiability block, four task Verification fields, two `tdd` anti-patterns, and two defect-class rows (`changes/gate-falsifiability`).** `/akili-specify` Step 3.2 extends the existing falsifying-input rule with a **Falsifiability** block beneath the KZ-006 bullet: six named rules — *Expressible falsifier*, *Assertion-level red run*, *Real-artifact lock*, *Compile gate*, *Consumer Sweep*, and a *Rendered-measurement checklist* (baseline, fonts, real geometry, two viewports, effective CSS px with zoom, clip containment) that applies only when a gate asserts size, overflow, visibility, position, or containment. Every task now carries four named Verification fields — `Falsifier`, `Red run`, `Disqualifier`, `Consumers` — with the absent-value rule (`n/a`/`none`, never blank); the fields are named in `/akili-specify`'s task list and Verification Checklist, and in the scaffolded `docs/specs/general-setup/task.md` template description (`/akili-constitution` Step 7 item 3). The `tdd` skill gains two anti-patterns — **inert fixture** (a fixture the named mutation can't discriminate) and **plumbing test** (a test that proves its own fragment, not the shipped artifact) — plus a red-fails-on-the-assertion clause in "Red before green" and an extension to the Implementer's cited-red evidence row (names the assertion it failed on; a setup red is reported as not-a-red). `/akili-specify`'s Step 1.2 defect-class table gains two rows: a *compiler-only defect* (gate: build/type-check) and a *layout/geometry defect* (gate: a rendered measurement, or the existing HITL/T6 substitute). Mirrors (`docs/commands/akili-specify.md`, `docs/skills/tdd.md`, `docs/commands/akili-constitution.md`) brought to parity.
- **Optional `Integration Branch: <name>` constitution pin, confirmed with the user and never inferred.** `/akili-constitution` Step 8 offers a second pin, written immediately after `Default Branch:`, for projects that route spec branches through one shared integration branch before it reaches the default branch. Detection is a direct question — never a branch-name heuristic or merge-history inference — takes exactly one name distinct from the default branch, and Safe Update adds it only when absent, never rewriting an existing pin.
- **Apply Mode re-verify step and the `superseded` status.** Before writing each HITL-approved pending item, the `kaizen` skill's Apply Mode now runs one bounded probe (Target exists at HEAD, plus the one fact the `Edit` names); a refuted item closes as `superseded (reason)` instead of being written, and an unverifiable one is presented to the user rather than guessed.
- **Upstream report, `Kind: upstream`, and the `upstreamed` status.** Methodology lessons (and the upstream half of a dual Product + Methodology lesson) are now recorded as a `Kind: upstream` pending item on any branch. Apply Mode collects every approved one into a single `docs/specs/kaizen/upstream-<date>.md` report and flips them to `upstreamed (date, report)`.
- **Leader brief contract, runtime-event ladders, and the `REVIEW_WAIVED` waived-close record (`changes/leader-brief-contract`).** `/akili-execute` Step 2.2 gains a five-clause **brief contract** — narrow-never-widen, convention files named by a bounded lookup, every third-party fact source-or-`UNVERIFIED`, any Leader-added item tagged `[advisory-grade]` (audited only, never gating), and the task's `Falsifier`/`Red run`/`Consumers` fields copied alongside the command — governing what the Leader may put in an Implementer brief; `leader.md`'s Delegation Discipline gains the matching principle paragraph. Step 2.3's Reviewer instructions become a **report contract**: the returned message's first line is `STATUS:` — nothing before it — in a fixed order under a ~600-word ceiling, with overflow issues written to a scratchpad file the Leader reads by path; `reviewer.md`'s Structured Review Output section carries the same contract. The Step 2 preamble names a **runtime-event** vocabulary — spawn failure, provider-limit death, pane/terminal timeout, idle-without-report (pointer to `leader.md`) — with one accounting rule (an attempt is consumed only by a Reviewer `FAIL` or an Implementer-reported verification failure, never by a runtime event) and a per-role recovery ladder (Implementer: five rungs ending in a Leader-inline ask; Reviewer: four rungs, never inline, ending in the waiver record), each event kind entering at a fixed rung (a provider-limit death whose worker context survives goes straight to resume-by-message) and a later event in the same attempt continuing the climb from the higher of the rung already reached and its own entry rung — a spent rung is never re-run, a rung whose condition does not hold is skipped, and the attempt's `runtime events:` line names every event and the one rung that recovered it; `leader.md` item 4 cites the same accounting rule and renames "HALT + Automatic Rollback" to "HALT + rollback by tree state". The Execution Log Format gains `## REVIEW_WAIVED: <Task ID>` (flag ∈ `inline`/`same-model`/`degraded-pair`, cause, user approval, the verification that stood in, models) and the final-status vocabulary becomes `PASS` / `WAIVED (flag)` / `HALT` / `pivot`; `reviewer.md`'s Audit Checklist gains an item for the red run and mutation trace (hand-off from `changes/gate-falsifiability`) plus a 4R clause auditing `[advisory-grade]` items in `ADVISORY` only.

### Changed

- **Apply Mode and `/akili-archive`'s shared-file gates now run on one apply-capable branch, never two.** The `kaizen` skill defines an exclusive predicate — the pinned integration branch when the `Integration Branch:` pin exists, otherwise the default branch, never both — and the default branch is held to the spec branch's non-writing rule while a pin stands. `/akili-archive` Step 3's gate, Step 4.4's backlog offer, and Step 6's report all cite this predicate by name instead of comparing against the default-branch pin alone; Step 6 now reports all five standardization states (`applied`, `deferred`, `pending`, `superseded`, `upstreamed`).
- **The `## Active Lessons` digest is normalized before every refresh.** Apply Mode dedupes existing rows by `ID` and re-enforces the 10-row cap before adding new rows, closing drift a hand-edited or pre-pin digest could carry.
- **`/akili-resume`'s Kaizen footer names the pinned apply-capable branch and counts only `pending`/`deferred` items**, explicitly excluding `applied`, `rejected`, `superseded`, and `upstreamed` from the backlog count.
- Root guides (`AGENTS.md`, `README.md`, `docs/flow.md`, `docs/README.md`, `docs/skills/kaizen.md`, `docs/skills/README.md`), the `akili-archive`/`akili-resume`/`akili-constitution` command mirrors under `docs/commands/`, and the packaged `leader.md`/`implementer.md` guardrail phrase are updated to the apply-capable-branch wording throughout.

- **Four Kaizen standardizations from the `changes/gate-falsifiability` and `changes/leader-brief-contract` retrospectives (Apply Mode, default branch, 2026-09-19):** `/akili-specify` Step 3.2 gains the bullet *a walkthrough over the cases its rules cite is an inert fixture* (a closure walkthrough names at least one held-out case and judges the general sentence with its example stripped), and Falsifiability rule 1 now requires that a `Falsifier`, verification count, or expected outcome stated as a present-tense reading is run or walked before it is written; `reviewer.md`'s Requirement Conformance item walks each cited FR statement, table and every paragraph under it term by term (a missing requirement obligation is never an ADVISORY); `leader.md`'s pre-review restatement sweep also reads every paragraph that received an insertion, whole. The `## Active Lessons` digest gains four rows and retires four institutionalized ones.
- **Two Kaizen standardizations from the `changes/kaizen-loop-closure` retrospective (Apply Mode, default branch):** `/akili-specify` Step 2.2 gains the guideline *new enumerated values walk their consumers*; `leader.md` item 4 gains the *pre-review restatement sweep* for rules documents. `AGENTS.md`'s installer line now names all four install targets (factual sweep).
- **Diff-by-size delivery, HALT rollback scoped to tree state, and the `/goal` waiver condition (`changes/leader-brief-contract`).** `/akili-execute` Step 2.3's Reviewer diff delivery is no longer always inline: a diff of ≤300 lines stays inline, above that the Leader writes it to a scratchpad file the Reviewer `Read`s by path (a non-host Reviewer keeps the inline exception at any size); `reviewer.md`'s mode table gains the matching note. Step 4's HALT rollback now branches on tree state instead of an unconditional restore: a clean tree still gets the blanket `git restore .` / `git clean -fd`, a tree holding other PASSed work restores only the halted task's own file paths (never a directory glob), and unattributed changes are never restored and are escalated to the user. Step 5's `/goal` canonical condition now reads "matching PASS or `REVIEW_WAIVED` evidence", since a waived task would otherwise never satisfy it, and both the waiver decision and the Leader-inline ask are added as stops under `pre-approved`. `/akili-resume` Step 1, the `kaizen` skill (Measure table row, clean-run predicate, Metrics example), and `/akili-archive` Step 4.1 each gain one clause naming a `## REVIEW_WAIVED` close.

### Notes

- Release classified **minor**: the batch adds new behavior other commands consume — the optional `Integration Branch:` constitution pin, the `upstream` Kind with the `superseded` / `upstreamed` statuses, and the `## REVIEW_WAIVED` record with the `WAIVED (flag)` final status read by `/akili-resume`, the `kaizen` skill, and `/akili-archive`. `changes/gate-falsifiability` alone would have been a patch (guidance refinement). No new command or install target; no breaking change — existing `tasks.md` and `execution.md` files stay valid without migration.
