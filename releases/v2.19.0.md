# v2.19.0 - AKILI-SPECS methodology update

Release date: 2026-07-28

### Added — field findings from a complete cycle (MF-01…MF-06)

A user ran a full propose → archive cycle and documented six methodology findings. All six are real; two needed reframing before implementing. Applied:

- **MF-01 — Approval Mode: pre-approved cycles are now recordable instead of improvised.** Every command ends in a HITL gate, but when the user pre-approves the whole cycle up front the methodology had no way to *record* that mandate — the agent skipped gates ad-hoc, invisibly. `/akili-propose` Document Control now carries `Approval Mode: gated (default) | pre-approved (<who>, <date>)`, inherited by specify (each phase gate logs `auto-approved (pre-approved mode)` in its document) and execute (the Step 5 continue gate auto-passes after a PASS, logged in `execution.md`). The critical boundary: **pre-approval covers routine progress, never exceptions** — HALT, Pivot, budget tripwire, `FATAL_FAIL`, `PRODUCT_BUG`, destructive actions and `/akili-quick` escalations always stop regardless, because their content is unknown until they fire and therefore cannot have been pre-approved. Judgment-day always runs — the mode skips *pauses*, not *review*.
- **MF-02 — the factual-claims sweep escaped the per-module loop it was trapped in.** `/akili-archive` Step 3 *already* said "update any root-guide statements the change made stale" — but as a sub-bullet of "for each impacted module", so it only fired for modules the impact notes named. That is exactly how a cycle that shipped ten components left `CLAUDE.md` still asserting *"No application code yet"*: no single module impact pointed at that sentence. The sweep is now a standalone step that **runs always, even with zero impact notes**, scanning the root guides for assertions the cycle falsified (CodeGraph status lines, project-stage claims, stack/command statements, counts). A constitution that states falsehoods trains every future agent on them.
- **MF-03 — the model checkpoint now checks direction: the registry is a floor, not a ceiling.** All eleven command checkpoints fired on "registry maps the tier to a model *different* from the session model" — and *different* has two cases. A field registry pinned to a dated model (violating its own alias-first rule) made every session on a newer-generation model receive the inverse recommendation: downgrade. Canonical rule in `docs/model-routing.md` + the operational line in all 11 checkpoints: when the **session model is the stronger one**, the checkpoint passes silently and the finding is a **stale registry entry to flag for update** — never a downgrade to recommend. The finding's third proposal (refresh cadence) was already covered: `/akili-audit` ships a Model Registry Drift check and each release refreshes the packaged defaults.
- **MF-04 — `/akili-propose` no longer interpolates a paragraph into a directory name.** The single `<change-name-or-spec-path>` argument, given free-text intent (the real invocation in the field), rendered spec paths like `changes/<60-word-paragraph>`, and the agent's silent slug inference was never requested nor recorded. The signature is now `<slug-or-path> [free-text context]`, with the rule: an argument that reads as a sentence is **never** a path — derive a kebab-case slug (≤4 words), record the derivation in Document Control, and treat the text as proposal context. Review Checklist enforces it.
- **MF-05 — delegation mode is declared, never implicit.** A design delegation launched in background left the coordinator mute for ~13 minutes; the user interrupted twice — correctly, because a silent background wait is indistinguishable from a hang. This is 2.17.7's announced-wait lesson surfacing inside `/akili-specify`, which had no equivalent rule. Now it does: every delegation in an interactive phase is either synchronous with its expected duration announced, or backgrounded with an explicit return notice; no signal within the announced window → inline fallback, said out loud.
- **MF-06 — runtime failure has a per-role fallback path instead of improvisation.** When the harness itself failed to spawn (tmux `terminal_exited`), no command said what to do; the coordinator improvised an inline fallback that happened to work but was unaudited. `/akili-execute` now defines the degradation per role: **Implementer** → ask the user to approve Leader-inline (the no-code rule stands — runtime failure does not waive it); **Reviewer** → **never inline**, because self-review breaks `author ≠ auditor` and a runtime failure does not suspend a correctness constraint — offer a different model, a cross-host dispatch, or an explicit recorded waiver; **Tester** → the `/akili-test` Deployment Rule's existing inline path. `/akili-specify`'s delegated roles (designer, scout) degrade inline safely — no independence constraint applies to them.

### Added

- **A user without the CodeGraph CLI could run the methodology forever without learning it exists — and worse, without the analysis it powers.** Field report: a methodology user had no `codegraph` binary, so the discovery analysis "didn't happen." Two distinct defects hid under one symptom. **(1) "Unavailable" was a permanent, silent state.** The four-state control from 2.17.8 made the *skip* visible, but no path ever told the user *how to stop being in that state*: the init offer fires only when the CLI is already installed, so the one user who needs the install command is the one who never sees any prompt at all. `/akili-constitution` and `/akili-audit` now say it in one line when the CLI is missing — install `@colbymchenry/codegraph`, then `codegraph init -i` — and keep going; `akili doctor` gains an **Environment (recommended, not required)** section that detects the binary, prints the same remediation when absent, and never flips the exit code, because a missing recommended tool degrades scan confidence, it does not break the installation. README documents it under Prerequisites with the same framing. **(2) "No graph" had quietly become "no analysis."** The fallback was documented but the scope rule was not, and the gap is exactly the class 2.17.8 named: *"optional" means the user chooses the tool, not that the analysis may disappear*. Both commands now state it as a rule: **absence changes the tool, never the scope** — every extraction and every drift category still runs at full depth via `Glob`/`Grep`; a missing graph makes the scan more expensive and its confidence lower (which the reports already record), never smaller.
