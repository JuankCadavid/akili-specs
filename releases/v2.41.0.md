# v2.41.0 - AKILI-SPECS methodology update

Release date: 2026-11-01

### Added

- **A Design Routing Matrix, `impeccable-bridge/references/design-routing.md`,** maps each design activity and environment to one lead skill, the playbook, the craft floor and `polish`.
- **A `Design route:` line on UI tasks** in `tasks.md` records the matrix pick for the task.
- **`/akili-constitution` Step 8D scaffolds a `### Design routing` block** in the project `## Skill Map`, for projects with a user interface only.
- **Repo `AGENTS.md` gains a `## Design Skills` section** naming the eight design skills and pointing at the matrix.
- **`golang-pro` is now a packaged `stack` skill (32 packaged skills, was 31).** It is vendored from `Jeffallan/claude-skills` at commit `078a25cc5bfd8011459be7b91d004e900c1d02d3` under `.claude/skills/golang-pro/`, under the MIT license. The folder holds `SKILL.md`, five `references/` files, the upstream `LICENSE` byte-identical, and a `NOTICE` that names the holder, the source, the pin, the frontmatter-only change and non-affiliation. The only change to upstream is four `metadata` keys appended to the `SKILL.md` frontmatter (`source`, `adapted-by`, `adapted-for`, `binding: stack`).
- **It was security-reviewed at the pin, and skills.sh rates it "Fail".** The AKILI review (spec task T1) found no injection and no fetch-and-run instructions in the pinned files. skills.sh labels the skill "Fail" and its Trust Hub page states Risk Level CRITICAL (audited Oct 27, 2026), on the finding quoted in the AKILI T1 record, `EXTERNAL_DOWNLOADS`, on the documentation link in the last line of `SKILL.md`; the page counts 2 flagged URLs and names 1. By the maintainer's decision the link is kept byte-identical and inert: AKILI adds no instruction to open it, and `NOTICE` and `docs/skills/golang-pro.md` record the finding.
- **`golang-pro` is offered in the four stack-skill candidate pools.** These are the `/akili-constitution` Step 5 list and its Step 8D `## Skill Map` candidates, the `/akili-specify` Step 2.1 fallback list, and the stack-skills line in `docs/commands/akili-constitution.md`. No command step tells an agent to load it. `docs/skills/golang-pro.md` documents it, and the skills inventory, overview and governance tables list it.
- **`test/golang-skill.test.js` hash-locks the vendored folder.** It hashes raw bytes as git blobs: the five references and `LICENSE` equal their pinned SHAs, and `SKILL.md` minus the four added lines equals its pinned SHA. It also checks the frontmatter keys, the `NOTICE` facts, the four pools, the governance row, that nothing under `.claude/skills/` has `samber` in its path, and that the folder stays under 60 KB. `.gitattributes` marks the folder `-text` so Windows checkouts keep the bytes LF.
- **`samber/cc-skills-golang` is documented as an optional complement and is never vendored.** The user installs it with samber's own installer; no file from it is in this repository.

### Changed

- **The bridge build row is now playbook, craft floor, then `polish`, code-led.**
- **`/akili-specify` records an environment class and a motion rule;** `/akili-propose` offers the Impeccable picker first and Stitch on request; `/akili-seo` runs through the bridge.
- **Leader and Tester persona skill examples** name the routed design skills.
- **The AKILI sections of `ui-ux-pro-max`, `gsap-animation` and `frontend-design`** point at the matrix.
- **The design-evaluation rules address 14 gaps found in the first `/akili-audit design` run on 2.40.0.** The changes are rules text in `impeccable-bridge`, its `references/design-evaluation.md`, `/akili-audit`, `/akili-validate`, `/akili-constitution` and `/akili-propose`, with a text-contract test (`test/design-eval-contract.test.js`). The vendored `impeccable/` skill is untouched. The installer item from the same audit is handled by the install and doctor entry below.
- **`install` classifies every skipped entry, and `doctor` warns on stale ones.** Skip lines read `(identical)` or `(differs: <names>)`, the summary splits `skipped N (identical I, differs D)`, and next steps name `akili update` or `--force` only when something differs. `doctor` reports `DIFFERS` as a warning: exit code and status are unchanged and `--fix` never overwrites it. A global install whose roots lie under the home directory prints a `Home:` line. `docs/cli.md` documents `--local` per git worktree.
- **Engine isolation and copy integrity.** After a consented download, the bridge pins `IMPECCABLE_BIN` to the binary it wrote and passes it inline on every launcher call, because `IMPECCABLE_HOME` alone does not isolate: each launcher reads `~/.impeccable/bin/impeccable[.exe]` first. A user exclusion of `~/.impeccable` is honored and recorded, and under an exclusion only the one download call changes the home variable, unsets `IMPECCABLE_BIN` and drops excluded `PATH` entries. Step 0 hashes the vendored copy against its `UPSTREAM.md` and records `vendored (<version>, verified)` or `modified`, plus the copy path, what `~` resolved to and any other copies, never selecting another one.
- **The first-visit pass is stricter.** Its browser captures run at every first-visit viewport: `desktop`, `mobile` and a new short-height pair (default `1366x768` and `375x667`). The short-height pair is browser-only, so the detector scan matrix stays at two passes. Each capture reads `pass`, `covered (<element>)`, `below fold (y=<n>)` or `Unevaluated (<reason>)`; `below fold` is never reported as `covered`. The primary CTA comes from a new `Primary CTA` column in the Screen Inventory, falling back to a recorded method, and visibility is measured from computed style and the bounding box. A consent banner must be seen on screen; when it is not, a would-be `pass` reads `Unevaluated (consent banner not rendered: <reason>)`, while `covered` and `below fold` stand, and the detector's first-visit flags count as evidence only where the banner was confirmed. Every viewport is `WxH`.
- **The `SKILL.md` strip before hashing is byte-exact.** It keeps a missing final newline, because the vendored `SKILL.md` has none and a strip that appends one prints a different hash. Step 0 *Verify* now names a `node -e` reference command that prints the hash to compare with `UPSTREAM.md`.
- **Report-only mode skips three Impeccable `critique` steps.** `/akili-audit design` no longer persists the `.impeccable/critique/` snapshot, starts `live-server`, or asks closing questions. Assessment A runs as an isolated sub-agent given no detector output, and a delegated E4 brief must require the finding count first and the findings as text in bounded parts, and forbid file output. The parent checks the received findings against that count before writing.
- **Reference and report changes.** Priorities gain a mapping (Impeccable P0 becomes P1 tagged `blocking`). E2 picks screens so every page template appears once while the cap of 8 allows and reports the rest in a `Coverage` field. E3b may run `npm ci` with consent in a fresh worktree, counts a Lighthouse run by its JSON rather than its exit code, and records machine load. E1 routes a missing page-mode column, waiver list or clause ID to `/akili-constitution` without writing. The report template and checklist carry the new fields.
- **`/akili-constitution` numbers approved design clauses** (`<n>-<nn>`) so a waiver or a proposed waiver can cite one. A new `false positive (<reason>; <evidence>)` value in `/akili-audit design`, limited to a closed list that starts with `text-occlusion` inside `aria-hidden="true"`, is counted in a `False positives` header field and never appears among P1-P3.
- **The report location follows E6 everywhere.** `/akili-audit` step 5 and its checklist, `/akili-propose` and the docs accept a user-directed path as well as `docs/specs/audits/`. `/akili-validate` asks for the manual fold check at every first-visit viewport.

### Notes

- **Existing installs keep a differing `impeccable-bridge` folder until `akili install --force`.** Deployed personas upgrade with `akili doctor --agents --fix`.
- **Release class: minor** (new design-routing behavior: the routing matrix, the `Design route:` line on UI tasks and the Step 8D `### Design routing` block; a new vendored `stack` skill, `golang-pro`; no new command or install target).
- **Upstream request.** Three behaviors only Impeccable can fix (the launcher's `~/.impeccable` order, the detector's first-visit flags with custom banners, and `aria-hidden` occlusion) are drafted as a request, not filed. AKILI works around them with the rules above.
