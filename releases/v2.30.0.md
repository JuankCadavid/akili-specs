# v2.30.0 - AKILI-SPECS methodology update

Release date: 2026-10-01

### What to do in your project (upgrade guide)

**In one line:** update the CLI, then run `akili doctor --agents --fix` in each project that has an `.agents/` folder. Your customizations are kept; a backup is written before anything changes.

| Step | Command | What it does |
|---|---|---|
| 1. Update the CLI | `npm install -g akili-specs@2.30.0` (or `akili update`) | Refreshes the installed commands, skills, templates **and the new `templates/digests.json`**. Until you do this, plain `akili doctor` reports that one file missing (`INCOMPLETE`, exit 1) — expected, not a defect |
| 2. See the drift | `akili doctor --agents` | Read-only. Compares your `.agents/*.md` personas, section by section, against the templates this release ships. A persona scaffolded on any earlier release reads `unmarked` (exit 1) |
| 3. Preview the fix | `akili doctor --agents --fix --dry-run` | Prints the full plan and runs every guard; writes nothing |
| 4. Apply it | `akili doctor --agents --fix` | Backs up each persona to `.agents/.backup/<role>.md.<timestamp>`, then upgrades it. **A persona from an earlier release needs this twice:** the first run *fences* the sections it recognizes (they then read `outdated`), the second run *replaces* them |
| 5. Confirm | `akili doctor --agents` | Exit 0 means you are current. Commit `.agents/` |

**What is preserved, what changes, what to look at afterwards**

- **Preserved, byte for byte:** everything you added — front matter, the `<!-- akili:project -->` … `<!-- /akili:project -->` block, any text outside an owned section (the one exception: line endings are normalized to the file's majority style).
- **Replaced:** only AKILI-owned sections whose text is an earlier release's (`outdated`), plus sections the template has and your persona lacks (`missing`).
- **Left alone and reported:** `custom-edited` (you changed an owned section by hand — move that text into the project block, or force the replacement with `--fix --section <id>`), `unlocated` (a template section the migration could not find in your persona — usually a guardrail your scaffold predates; insert it with `--fix --section <id>`), `extra` (a section the template no longer has).
- **Guards:** the fix refuses to write off your project's apply-capable branch (the `Integration Branch:` / `Default Branch:` pin in your root guide, or the resolved `main`/`master`) unless you pass `--allow-branch`, and refuses on a dirty `.agents/` unless you pass `--force`.
- **Rollback:** copy the file back from `.agents/.backup/`.
- **From now on,** put every project-specific instruction in the project block, never inside a marked section — a marked section is what the next upgrade replaces. `/akili-constitution` Safe Update follows the same rule and runs this command for you; `/akili-audit` reports personas that are behind.

Full reference: `docs/cli.md` → *Persona Drift (doctor --agents)* — marker grammar, every state and exit code, every `--fix` row.

### Changed

- **Deployed personas get an upgrade path: section markers, a project block, `akili doctor --agents [--fix]`, and a Safe Update that replaces instead of appending (`changes/persona-upgrade`).** The four packaged templates (`leader.md`, `implementer.md`, `reviewer.md`, `tester.md`) now fence every AKILI-owned block with `<!-- akili:section id=<id> since=<release> -->` … `<!-- /akili:section -->` markers — HTML comments, invisible once rendered as Markdown — and each carries exactly one `<!-- akili:project -->` … `<!-- /akili:project -->` block, placed right after the primary instructions, where every scan-derived injection and hand customization now lives; a rule an owned section states and the project block contradicts resolves in the project block's favor, and each template says so in one sentence ("The project block below overrides any marked section."). **22 section ids changed, by template:** `implementer.md` — `context-alignment`, `scope-discipline`, `craft`, `verification`, `reporting`, `shared-file-discipline`; `reviewer.md` — `read-only-role`, `audit-checklist`, `structured-evaluation`, `lenses`, `depth-scaling`, `review-output`; `tester.md` — `context-alignment`, `prove-behavior`, `incremental-focus`, `bounded-loop`, `test-report`; `leader.md` — `primary-instructions`, `delegation`, `test-harness`, `reporting`, `shared-file-discipline`. The four templates total 74,391 bytes, under the 74,421-byte cap the marker budget allows. A new CLI mode, `akili doctor --agents` (`--fix`, `--section <id>` repeatable, `--allow-branch`, `--force`, `--dry-run`), runs against a project's own `./.agents/` and reports one state per section against the CLI's own packaged templates and a shipped digest table (`.claude/templates/digests.json`): `current`, `outdated`, `custom-edited`, `missing`, `unlocated`, `extra`, `unreadable`, `unmarked`, or `absent` (the persona file) — `current`, `custom-edited`, `extra` and `unlocated` stay the maintainer's own call and never fail CI; every other state does, and so does an absent `.agents/` folder. `--fix` replaces every `outdated` section (rewriting its `since=`), inserts every `missing` one at the template's position, migrates every `unmarked` persona (fencing only text it can match by exact body or by a paired heading-and-opening-sentence signature — a retitled or rewritten section is reported `not located`, never guessed at), and installs the packaged template for an `absent` persona file — backing up the original to `.agents/.backup/<role>.md.<timestamp>` before any write, and never changing a `custom-edited` or `unlocated` section, an `extra` one, or any byte of project space (the project block and everything outside an owned section; line endings are normalized to the file's majority EOL) unless `--section <id>` names it. `/akili-constitution`'s Safe Update bullet (Step 8B) and `/akili-audit`'s existing persona-structure check (item (c)) both now run this mode, or its by-hand equivalent from the installed templates and digests when the CLI is unavailable, in place of the old "append a minimal upgrade block" rule, which is removed everywhere it was stated (`.claude/commands/akili-constitution.md`, `docs/commands/akili-constitution.md`, `docs/flow.md`, `README.md`, `.claude/commands/akili-audit.md`). **What a maintainer runs:** `akili update` to refresh the installed templates and `digests.json`, then `akili doctor --agents --fix` in each project — `--dry-run` first to see the plan, on the project's apply-capable branch (its `Integration Branch:` or `Default Branch:` pin, or the resolved `main`/`master`; `--allow-branch` overrides an unresolved branch, `--force` overrides a dirty `.agents/` tree). **The seeded legacy table:** `digests.json` ships a `legacy` table, generated once from every git tag whose tree carries a `.claude/templates/<role>.md` — **73** tags for `leader`, `implementer`, and `reviewer`, **48** for `tester` (whose template first shipped at v2.5.0) — **1,199** hashed section entries in all, so a persona scaffolded on any past release, or hand-rewritten with renamed items (the shape seen downstream: one-space numbered items, two retitled, no `## Authorship`), can still be recognized and fenced rather than read as a wall of `custom-edited` text. The release-by-release `digests.json.releases` table starts empty at this release and is written densely — every section of every role, at every release — from here forward by `scripts/release.js`. **Rollout and rollback — nothing runs until a maintainer runs the command:** a project that never runs `doctor --agents` is unaffected; the markers are comments, and plain `doctor` (without `--agents`) keeps its own code path unchanged. **What an existing installation will see:** because `doctor`'s resource check now also expects `.claude/templates/digests.json` (DD-11), `akili doctor` on a project installed before this release reports that one file missing — and the whole target `INCOMPLETE`, exit 1 — until a maintainer runs `akili update` (or `akili install --force`) to populate it; CI installs fresh before it runs `doctor`, so a CI run never sees this. A `--fix` is reversible by restoring the backup the report names. **Known gaps, stated here rather than left to be assumed otherwise:** `akili doctor --help` does not yet list `--agents`, `--section`, or `--allow-branch` — a carried spec gap, owned by no task in this change; and while the CI matrix (`ubuntu`/`macos`/`windows` × Node `18`/`22`) now runs `npm test` on every push to `master` and every pull request, the first `windows-latest` and `node: 18` legs have not run yet as of this entry — CI **runs** the suite, this entry does not claim it has **passed** on every leg. **The convention from this release on:** a CHANGELOG entry that changes a persona names the section ids it changed, as above, and carries no hand-migration recipe — the command does the migration. This entry adds to, and replaces nothing in, the v2.29.0 note below.

- **Kaizen standardizations from `changes/persona-upgrade` (three, applied 2026-10-01 on `master`):** `/akili-execute` Step 0 now runs `akili doctor --agents` before the first spawn and treats `outdated`/`unmarked`/`missing` personas as a stop — a rule stated only in the brief is not enforced (7 of 26 spawns ran past the 60-call bound with a stale deployed persona); its *Pivot Detection* rule names a **spec tension** (two approved clauses the code cannot both satisfy) as the lightest Pivot evidence, settled at the next gate as a one-line amendment and never carried to closure; and the `tdd` skill's *Verification evidence* row makes each red a quoted expected/actual pair by test name, with a throw before the assertion written as "not red". The Active Lessons digest gained three rows, merged three recurrences (KZ-002 → High, KZ-changes--leader-brief-contract-2, KZ-changes--kaizen-loop-closure-2) and retired three applied rows (KZ-001, KZ-changes--leader-brief-contract-1, KZ-changes--scoped-constitution-reads-2). Constitution sync: `AGENTS.md` names `bin/persona.js`, `test/` and `digests.json`, adds `npm test` to *Verification*, and notes the release script's wider `git add` hint; `docs/release-checklist.md` likewise.

### Notes

- Proposed classification: **minor** — a new, opt-in CLI mode and template marker format; no existing project is forced to adopt it, and a project that never runs `akili doctor --agents` sees no change to any persona. Plain `doctor` (without `--agents`) is a narrower claim: its code path is unchanged, but its reported outcome for a pre-existing install is not — see the entry's "What an existing installation will see" paragraph above (DD-11).
