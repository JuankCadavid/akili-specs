# v2.29.0 - AKILI-SPECS methodology update

Release date: 2026-09-30

### Changed

- **Implementer and Tester personas now read reference documents by section instead of whole, and the cross-worker caching claim is removed (`changes/scoped-constitution-reads`).** Both personas' item 1 first bullet — previously, byte-identical in both files: *"To maximize prompt caching, **FIRST** consult the project constitution (`CLAUDE.md`, `AGENTS.md`, `docs/trd/trd.md`, `docs/ux-ui/design.md`) in a consistent order before reading task-specific files."* — now reads the project's root guides (`CLAUDE.md`, `AGENTS.md`) whole, skipping one the project does not have, and reads each reference document (the TRD at `docs/trd/trd.md`, the UX/UI design at `docs/ux-ui/design.md`, legacy paths included) only at the sections the brief names, verbatim at the source, through a stated six-state table — sections named, `none`, the entry silent, a stale or ambiguous heading, the document absent from the project, or the work touching the document's domain anyway — so every state the entry can be in has an action and a lookup note is never mistaken for a gap. `/akili-execute` (the Implementer brief, Step 2.2) and `/akili-test` (the Tester's context slice, Phase 1) both now require the same per-document entry — named sections or the word `none`; an omitted entry is not a valid empty state — and record a worker's lookup note in a slot each report already has (`/akili-execute`'s task-entry `issues encountered`; `/akili-test`'s Summary). **Nothing updates a deployed persona automatically:** for a project scaffolded before this change, `/akili-constitution`'s Safe Update never overwrites an existing `.agents/*.md` file, only appends an upgrade block, so a maintainer of such a project must replace the quoted sentence above by hand in both `.agents/implementer.md` and `.agents/tester.md`. Until they do, `/akili-audit` reports the surviving sentence in `tester.md` as persona injection bleed — it still carries the design-token path the Tester disclaims — but does not report the surviving sentence in `implementer.md` as stale; there, only the new rule's absence is reported, under the structural-drift check. Measured on one project's (STAR) document sizes, not on token telemetry: the expected upfront load for a brief naming two to four sections is a computed **range**, not a fixed saving — about 8,338–13,668 tokens (root guides at 31,710 bytes, plus two to four named sections of 822–5,740 bytes each, at 4 bytes per token), down from about 28,037 tokens for the old four-document read (112,149 bytes ÷ 4).
- **`/akili-specify` bounds a rules-document task by what one review can read (kaizen apply, `changes/subagent-context-budget`).** Step 3.2 gains one task-quality rule: a task whose scope lists more than about eight edit sites, or sites in more than one rules document, is split per file — a Reviewer reads the changed text whole and stops at the first contradiction, so a 17-site task took five review rounds with three defects present from the first attempt.
- **`/akili-specify` re-measures a numeric cap against the drafted design (kaizen apply, `changes/subagent-context-budget`).** Step 2.4 gains one rule: a cap a requirement fixed before its content existed (persona bytes, file lines, table rows) is measured against a plain draft at the design gate and raised or the content cut there, never met later by compressing obligations away — the case cost one review round and a Pivot.
- **`/akili-specify` gains a design rule for tables that restate a requirement (kaizen apply, `changes/scoped-constitution-reads`).** When the design re-draws a table the requirement holds, each cell is compared with the requirement's cell before approval, and a shortened cell still names every obligation of the cell it shortens.
- **`/akili-specify` budgets two review rounds per task for rules documents (kaizen apply, `changes/scoped-constitution-reads`).** When a spec's tasks edit text that other agents execute (personas, commands, templates), the Step 2.4 budget estimates two review rounds per task.
- **Implementer runs are bounded: a checkpoint-and-respawn exit, output discipline, bounded reads (`changes/subagent-context-budget`).** The Implementer's self-correction loop, previously unbounded ("You must fix your code and re-run the verification until it passes"), now stops at a bound — **3** consecutive same-failure verification cycles, or **60** tool calls, whichever comes first — and, with the task unfinished and no blocker, exits with a `STATUS: CHECKPOINT` report (seven fixed fields: Bound reached, Done, Remaining, Tree state, Tried and failed, Next step, Notes) when a fresh worker could continue from the report, else `FATAL_FAIL` on its existing terms. `/akili-execute` Step 2.3 gives the Leader one new action, **Respawn**: on `STATUS: CHECKPOINT` it starts a fresh Implementer with the original brief and the checkpoint report copied verbatim, consuming no rework attempt, capped at **2 checkpoints per task** (separate from the existing continuation cap) — a third checkpoint HALTs the task by the existing HALT step, with the cause recorded as the checkpoint cap. Command output entering the Implementer's and the Tester's context is capped at **100 lines**; a longer run sends its full output to the system's temporary directory, or a directory the project's version control ignores, and brings in only the result summary and the failing part, kept whole up to the limit. File reads are bounded for all three workers (Implementer, Reviewer, Tester): `requirements.md` and `design.md` are read only at the sections a brief points at, with anything else read via each persona's section lookup, the Implementer no longer opens `tasks.md` at all (the brief already carries the task), and a file of **400 lines** or fewer may still be read whole, with a larger file read by range. Each spawn's tool-call count, token total, and end state (complete, checkpoint, partial, fail, fatal, or died) is now recorded per spawn in each task entry of `execution.md`, as reported by the host — the Leader never estimates a figure the host does not report, and the record gates nothing. **Basis:** the baseline this bounds — Implementer spawns over 100 turns holding 53% of cache-read tokens, and Implementer whole reads of `tasks.md`/`requirements.md`/`design.md` in 99 of 219 reads (45%) — was measured from local session logs of two downstream projects (297 Implementer and 284 Reviewer spawns, August–September 2026), stated here as that measurement, not as a general claim about every project's usage. **Migration:** `/akili-constitution` Safe Update never overwrites an existing `.agents/*.md` file — it only appends an upgrade block and leaves the old sentences standing, so an already-scaffolded project keeps the unbounded loop beside the new bound until a maintainer edits it by hand. In `.agents/implementer.md`, replace: the sentence *"You must fix your code and re-run the verification until it passes"* (and the two sentences beside it governing when to report back and when to `FATAL_FAIL`); the *Don't stop short* premature-stop sentence, now ending *"…stopping because the turn ran long or a milestone landed, or a checkpoint before its bound"*; its *"Legitimate stops remain: …"* sentence (add the two bound exits to its list); and the sentence *"Open a full file when you are about to edit it"* (bring it in line with the 400-line rule). Also add to `.agents/implementer.md`: the new Bounded reads and Output discipline tables, the *Checkpoint report* block (the seven fields), item 4's loop term table, and the new *Reporting Completion* lead sentence naming a checkpointed task's last worker. Add the new Bounded reads table to `.agents/reviewer.md`; add the new Bounded reads and Output discipline tables to `.agents/tester.md`. The deployed `.agents/leader.md` needs its five sizing/outcome sentences (the rework-loop, concurrency-budget, and per-task Outcome-report lines that now name the checkpoint respawn and cap) applied by hand too. Update the packaged commands first — `.claude/commands/` in this repo, `/akili-execute` in a global install — since only they reinstall cleanly; a persona edited later than its command briefly leaves the Leader holding a status the old command text has no action for. **Follow-up:** FR-8's measurement is owed to the user after the first 30 Implementer spawns run under the new personas, against FR-8's three baselines: spawns over 100 turns (14% → under 3%); median peak context (188k to 207k by group → under 120k); whole reads of the three spec documents (45%, 99 of 219 → under 10%). **Not claimed:** any measured saving from this change; FR-8's measurement has not run. Proposed classification: **minor**.
