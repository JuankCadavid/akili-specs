# v2.18.0 - AKILI-SPECS methodology update

Release date: 2026-07-28

### Added

- **`author ≠ auditor` was structural on the model axis and merely instructional on the write axis.** Step 8E has pinned the Reviewer to a different model than the Implementer since 2.13.0, and `.agents/reviewer.md` opens by declaring the role read-only — but that second half was an instruction the model *complies with*, and a diff sitting one edit away from passing is precisely when compliance is most tempting. The Reviewer wrapper now carries the host's read-only restriction on **every** host, not just Antigravity: `tools: Read, Grep, Glob` on Claude Code (no `Bash` — the Leader extracts and passes the diff, so the Reviewer never runs a command; `Read`/`Grep`/`Glob` stay because the persona permits reading a full source file when the diff alone is ambiguous, and removing that escape hatch would manufacture FAILs), and the equivalent on OpenCode with its **version-varying** syntax confirmed before use. The prior text claimed `tools` was "where this host exceeds the others" — true when written, and the reason the enforcement stopped at one of three hosts. Restrict the Reviewer and **nowhere else**: a restricted Leader, Implementer, or Tester is a broken role, not a stricter one. The restriction is a SHOULD, not a MUST — where the syntax is unconfirmable, or a wrong tool name would hang the agent (the documented Antigravity failure mode), **omit it and say so in Step 9**. An omitted restriction leaves the status quo, which works; an **unreported** omission is the actual defect, because it is indistinguishable from an enforced one. `.agents/reviewer.md` also now tells the Reviewer that missing write tools are deliberate, so it reports a `FAIL` with a remediation suggestion instead of an environment error.

### Changed

- **Token economy: the Leader paid every persona three times, and briefs converted cheap input into expensive output.** Three related fixes to `/akili-execute`, `/akili-test`, and the packaged personas, driven by the cost model that a file's price is its *multiplier* (how many times it re-enters context per run, and whether as cacheable input or as Leader **output** — roughly 5× dearer): **(1) Personas are read once, by the agent that runs them.** Step 0 read `implementer.md` + `reviewer.md` unconditionally and Step 2.2/2.3 re-sent "the persona content" on every spawn — but a Step 8E wrapper's entire body is the instruction to load its own persona, so with wrappers present the same text was paid in the Leader's input, again in the Leader's output, and again in the worker's context, up to six spawns per full rework loop. The Leader now reads only `leader.md` when wrappers exist and orchestrates against the roles' *contracts* (report shapes, `STATUS:` lines) rather than their persona text; the persona-seeded path survives intact as the no-wrapper fallback. `/akili-test` gets the same rule for `tester.md`, with the check that the persona file still *exists* either way — a wrapper pointing at a missing persona spawns a Tester with no contract. **(2) Pointer briefs for host workers.** Spec slices were copied into every brief; briefs now name path + section anchors with the instruction to read the named scenarios *verbatim at the source* — the verbatim rule protects against paraphrase drift, and a pointer satisfies it exactly as a quote does, as the worker's cacheable input instead of the Leader's output. The boundary is economy, not dogma: Reviewer FAIL feedback stays copied verbatim (Structured Feedback wins), Active Lessons stay copied rows (a pointer would trigger a bigger read), verification evidence stays copied (lives in no file), and the **git diff stays inline always** — ephemeral state no file holds, which the write-restricted Reviewer has no `Bash` to regenerate. Non-host workers keep the self-contained brief per 2.17.7. **(3) `execution.md` is read bounded.** Step 0.3 read the append-only log cover to cover, making every run of a spec cost more than the one before; routine task selection now reads Document Control + the `[~]` entry being resumed + the most recent entry, and the full read belongs to the moments that are *about* the history — `/akili-resume`, HALT investigation, Pivot.
- **CodeGraph was a Leader privilege; now it is a worker instruction.** The Delegation Thresholds have long exempted graph lookups from the Leader's read ceiling — but no worker persona or brief ever mentioned the graph, so Implementers, Reviewers, and Testers discovered code by full-file exploration in the projects where a semantic index existed precisely to avoid that. In codegraph-enabled projects the briefs now route each role to its natural lookup — Implementer: `codegraph_context` for the task area, `codegraph_impact` before touching a shared symbol, full files only for what it is about to edit; Reviewer: `codegraph_node`/`codegraph_callers` *before* the full-file escape hatch, which remains for what the graph cannot answer; Tester: `codegraph_search`/`codegraph_callers` to find the contract and usage surface of the code under test. Non-codegraph projects are untouched — every instruction is conditional on `.codegraph/` existing, and the graph's *absence* stays controlled where 2.17.8 put it (`/akili-constitution` offers init, `/akili-audit` records the four-state field, `/akili-archive` recommends the re-index). What routing workers to the graph newly exposed is **staleness**: the graph reflects the last index, and mid-run is precisely when it lags most — every completed task changes code that is not re-indexed until archive, and the graph cannot flag its own staleness, so a worker asking about a file the previous task rewrote gets a confident stale answer. Every consumption site now carries the boundary: **for files this spec already touched, the working tree wins; the graph is for the surrounding code the spec did not modify** — sharpest in `/akili-test`, where the code the graph lags on is precisely the implementation under test, and in the Reviewer, where a graph answer that contradicts the diff is stale rather than evidence of a defect.
- **`/akili-execute` Step 3 wrote the checkbox before the evidence, and the two writes are not atomic.** On a Reviewer `PASS` the Leader flipped `tasks.md` to `[x]` and *then* appended the `execution.md` entry. A run that ends between them — context exhaustion, an interrupt, a crash — leaves a completed task with **no record of why**, indistinguishable from an unverified completion, with the Reviewer PASS gone and unreconstructable. `/akili-resume` rebuilds state from `execution.md` and would skip it with nothing to flag. The order is now evidence-first, which inverts the failure state into the recoverable one: a task that is done but still reads `[ ]`/`[~]` gets re-run — wasteful, but the audit trail shows the PASS and the Leader reconciles. **Redundant work is cheap; an unfalsifiable completion is not.** This is a correctness fix on its own, and it is also what makes the ordering machine-checkable: a future gate on `tasks.md` writes can require the matching PASS to already be in `execution.md`, which is impossible under the reverse order because at the moment of the write the evidence does not yet exist. Mirrored in `.claude/templates/leader.md` (the persona actually loaded at runtime) and `docs/commands/akili-execute.md`.
