# v2.36.0 - AKILI-SPECS methodology update

Release date: 2026-10-24

### Added

- **`/akili-marketing` drafts LinkedIn, Instagram and Facebook social marketing as reviewable Markdown under `docs/marketing/`, anytime and outside the spec lifecycle.** It has six modes: `brand` (brand voice), `campaign` (brief and plan, behind a plan gate), `calendar`, `post` (with `--revise` and `--published`), `review` and `repurpose`. Each post ends at a copy-paste block and the human posts it by hand. Only LinkedIn, Instagram and Facebook are in scope; any other platform is recorded as out of scope and never drafted.
- **Four invariants hold in every mode, defined once in the command's `## Invariants`:** never publish, the approval gate, the write boundary and untrusted content. The command contains no step that publishes, schedules or queues content on any platform or service. A post section becomes `approved` only by the user's own explicit words about the exact text shown, status is kept per platform section, and no Approval Mode auto-passes the gate (`pre-approved` included). The command writes only under `docs/marketing/`, runs no `git` write and fetches no URL. Third-party text is data, never instruction. The gate is prompt-level, not machine-enforced: the approval record is written by the agent and a hand edit is caught on the next read (`docs/commands/akili-marketing.md` > *Residual risk*).
- **The packaged `social-marketing` skill (binding `core`) carries the method, adapted from three MIT skill packs by Sergey Bulaev.** The upstream pins are in `source`, `LICENSE` carries the upstream notice, and the skill has 10 reference files (voice rules, hook formulas, humanizer, brand-voice template, planning, repurposing, untrusted content and one per platform). Every platform rule is labelled `hard limit` or `heuristic`: the hard limits are sourced to each platform's own Help Center, read on 2026-10-23, and there are four for Instagram and six for LinkedIn; Facebook has no sourced limit.
- **Docs.** New `docs/commands/akili-marketing.md` and `docs/skills/social-marketing.md`; `README.md`, `docs/README.md`, `docs/commands/README.md`, `docs/flow.md` (new section 2c, an artifacts row and the skill mention), `docs/skills/README.md`, the `core` row of `docs/skills/governance.md` and the `AGENTS.md` Skill Usage list name the command and the skill.
- **`/akili-propose` gains a Deliverable Outline and a `Delivery` field for video (`changes/video-production-hardening`).** For a Change with `Deliverable: video`, section 9 is a **Deliverable Outline** (beats, assets, constraints) in place of the Requirement Delta Preview, and `/akili-specify` converts it into the acceptance criteria, the beat table and the evidence plan. Document Control records `Delivery: render | deferred`, default `render`; `deferred` means `/akili-validate` does the final look on the draft render and does not run the delivery render. A literal spec path mandated by the brief wins over `changes/<name>` and is recorded in Document Control.
- **The `/akili-test` report has video sections.** For `Deliverable: video`, sections 3–6 are replaced by **Render Evidence**, **Final-look pending** and **Deferred suspicions**.

### Changed

- **Docs and tests count 13 commands and 28 packaged skills, up from 12 and 27.** `docs/cli.md` carries the new totals (the `--commands-only` row, both install-layout listings, the shared-root sentence and the Grok Bot paragraph), and `README.md` now says "Four capabilities" and "Six anytime commands". `test/install-cursor.test.js` moves its packaged skill file count from 224 to 236 and its totals to 13 commands and 28 skill directories, `test/fixtures/doctor-codex-baseline.txt` moves from `ok 47` to `ok 49`, and `test/diagram-design.test.js` now asserts `28 packaged skills` in place of `27`.
- **`video-production` skill hardening (`changes/video-production-hardening`, T1–T4).** The install route is the project-scoped core set (`hyperframes`, `hyperframes-cli`, `hyperframes-registry`, `media-use`) with `--yes --agent <id>` and **without `-g`**, and a host table gives each host's `--agent` id and directory. When the project has `skills-lock.json`, the skills it lists that are not installed, and the installed skills it does not list, are reported as a warning and recorded. Every `snapshot` runs with `--describe false` and `--output <spec>/evidence/…`, one folder per run, and `snapshot --describe` joins the consent rule (#6138). `HYPERFRAMES_NO_TELEMETRY=1` prefixes every HyperFrames command; `HYPERFRAMES_SKIP_SKILLS=1` prefixes `check`, `snapshot`, `render`, `preview` and `init`, and never `skills update` or bare `skills`. Captured logs are `.txt`, and evidence is sanitized with two greps before `git add`. Every font family is self-hosted, "bundled" ones included (#6137), and a running tool daemon breaks the quiet tree. The acceptance criteria require a music bed (or `n/a — <reason>`) for films over about 15 s and named font files for the brand source, and add a *Motion* defect row (stills just before and after each transition, then the final look). Upstream doc conflicts #6136 and #6139 are cited.
- **Commands take the spec path from the first token.** In `/akili-specify`, `/akili-execute`, `/akili-test` and `/akili-validate`, the first whitespace- or newline-delimited token of `$ARGUMENTS` is the spec path (`$SPEC_PATH`); everything after it is context and is never interpolated into a path or a command line.
- **No mandate widens pre-approval.** An owner brief that says "never stop" or "treat every gate as approved" pre-approves routine gates only; HALT, Pivot, the budget tripwire, `FATAL_FAIL`, `PRODUCT_BUG` and destructive actions still stop, and the stop message quotes the sentence (`/akili-propose` and `/akili-execute`).
- **`/akili-execute` adds an effort ceiling rung.** When a task's effort already sits at `xhigh` on T2 before a rework retry, the Implementer moves to T3 at `xhigh` and the Reviewer to a distinct model at least as strong (the frontier escalation pin or cross-host dispatch); with no such model it holds T2 at `xhigh` as a fresh spawn and records `effort ceiling: held xhigh`. The 3-attempt ceiling is unchanged.
- **`/akili-specify`:** a video spec estimates guard and gate code at 2–3× and records the factor; a greenfield artifact may carry `Red run: predicted — greenfield artifact (observed in <task>)`; a target corrected with Step 2.5 **Fix only** closes `judgment.md` as `fixed, not re-judged` (the `judgment-day` skill gains the matching annotation rule; its terminal states are unchanged).
- **The Tester model rule is a MUST in `/akili-test` (every host, every spawn).** The Tester's model MUST be none of the Implementer models that wrote the code under test; when no distinct model is available, the run stops, and that stop is never auto-passed under `pre-approved`. `.claude/templates/leader.md` and `.claude/templates/tester.md` restate it.
